# V1.1.6 全项目自查报告

文档编号：`WD-V116-AUDIT-20260923`

## 本轮确认并修复

| 场景 | 旧行为 | V1.1.6 行为 |
| --- | --- | --- |
| 助手连续运行超过一天 | 只在启动时检查一次更新 | 到期后继续检查；开关变更即时参与判断 |
| 安装版与绿色版共存 | 只按 EXE 文件名判断启动项归属 | 精确匹配当前路径或本副本记载的旧路径；跨副本切换需确认 |
| 开机最小化后再次打开 | 第二次进程退出，原窗口仍最小化 | 通过当前会话信号唤回原窗口 |
| 保存设置时断电 | 删除旧文件与移动新文件之间可能丢失配置 | 同目录写穿暂存、文件替换、保留可读备份 |
| 普通安装覆盖失败 | 文件逐个更新，可能新旧混合 | 暂存、备份、异常反向回滚；中断时禁止运行并允许重试 |

## 回归边界

新增测试验证 24/48 小时计划、禁用与重启用、并发检查阻止；两个正式副本不互删启动项，移动旧路径可修复，确认期间变化的启动项不被覆盖；命名信号可恢复最小化窗口；设置主文件缺失时从备份恢复；多个替换步骤注入失败后旧程序及设置仍在；中断的首次安装可以重试。

既有测试继续覆盖官方客户端签名校验、精确进程退出、企业微信注册表恢复、更新下载摘要与回滚、代理、主题和不同窗口尺寸。CI 构建验证与真实腾讯客户端的登录后多开验证是不同层级；没有在 CI 中运行真实账号或上传用户聊天数据。

## 已知限制

- Windows 商业代码签名仍未启用，安全软件信誉提示仍可能出现。
- 若安装进程被断电终止，中断标记会阻止运行，用户须重新执行正式安装包；这不是后台静默修复。
- 客户端兼容性依赖腾讯官方签名、产品信息和当前单实例机制；腾讯未来版本改变该机制时仍可能需要项目更新。
- 尚无自动化的真实登录客户端兼容矩阵；发布时应记录实测客户端版本，不能把模拟进程测试解释成“所有版本均已实测”。
