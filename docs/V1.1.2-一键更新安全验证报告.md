# V1.1.2 一键更新安全验证报告

文档编号：`WD-V112-UPDATE-20260920`

## 1. 目标

V1.1.2 要同时解决两个问题：大量用户不能共同依赖 GitHub 未登录 REST API 每小时 60 次的额度；
减少 API 依赖时又不能降低一键执行安装包前的来源、大小和摘要校验强度。

## 2. 新的发现链路

1. 客户端访问固定地址
   `https://github.com/PascalePaF/wechat-wecom-duokai/releases/latest/download/update-manifest.json`。
2. 首个跳转必须落到本仓库 `releases/download/v<数字版本>/update-manifest.json`，不能含查询参数、
   片段、额外目录或其他主机。
3. 仅在发现版本高于本机版本时下载最多 64 KiB 的静态 JSON 清单。
4. 清单必须声明 schema 1、产品 `wechat-duokai`、同一版本/标签/发布页，以及规范 setup 和
   `SHA256SUMS.txt` 的名称、固定下载地址、大小与 64 位 SHA-256。
5. GitHub API 仅作为可选的独立摘要来源；不成功、超时或限流时使用静态清单继续。
6. 最新 Release 没有清单时，才进入兼容 V1.1.1 的普通 Release 跳转路径。

当前版本与最新版相同时只需解析固定跳转，不读取 REST API，也不下载更新附件。

## 3. 安装前校验

用户明确确认后，下载阶段依次执行：

| 层次 | 必须满足的条件 |
| --- | --- |
| 清单文件 | HTTPS、GitHub 交付域、64 KiB 上限、规范仓库/标签路径 |
| SHA256SUMS | 精确大小；文件摘要等于静态清单声明值 |
| setup 清单项 | `SHA256SUMS.txt` 中必须且只能有一条目标 setup 记录 |
| setup 元数据 | 文件名、URL、大小和摘要等于静态清单 |
| 本机下载 | 实际字节数等于声明大小；本机 SHA-256 等于清单项和静态清单 |
| 可选 API | API 可用时，setup 与 SHA256SUMS 的大小、URL、摘要必须与静态清单一致 |
| 启动前 | 文件锁持有期间再次计算 SHA-256，防止校验后替换 |

任何不一致均失败关闭，不执行下载到本地的 EXE。更新计划仍受安装/绿色版目录标记、父进程身份、
计划时效、同卷暂存、逐文件备份和失败回滚保护。

## 4. 请求调度

- 成功：下一次自动检查不早于 24 小时。
- 第 1 次失败：1 小时后；第 2 次失败：6 小时后；后续失败：24 小时后。
- `Retry-After` 或 `X-RateLimit-Reset` 可延后下一次自动检查，但总抑制时间封顶 24 小时。
- 远未来或损坏的本地时间值被视为无效，不能永久关闭检查。
- 启动错峰为同一安装路径稳定的 30–300 秒。本地路径仅参与 SHA-256 计算，不会写入 HTTP 请求。
- 手动检查始终绕过上述自动调度并立即发起。

状态文件为安装目录内的 `data\update-state.ini`，使用写穿临时文件和原子替换保存。它只包含检查时间、
失败次数和最近看到的版本，不含账号、聊天数据、设备标识或访问令牌。

## 5. 发布模型

构建脚本在 setup、绿色 ZIP 与 `SHA256SUMS.txt` 完成后生成静态清单，避免摘要循环。CI 重新解析清单，
逐个核对文件大小、SHA-256 和规范下载 URL。正式 Release 采用“先草稿上传全部附件，再发布”，并启用
GitHub Immutable Releases，使发布后的标签和附件不能被替换。

## 6. 回归范围

自动测试覆盖有效/恶意清单 URL、非 GitHub 跳转、API 403 降级、旧 Release 无清单兼容、24 小时缓存、
1/6/24 小时退避、服务器 Retry-After、损坏远未来状态、稳定错峰和原有事务式更新回滚。构建流水线还
验证 `SHA256SUMS.txt`、静态清单与 SPDX 2.2 SBOM。

## 7. 剩余边界

- 项目仍未购买商业代码签名证书，Windows SmartScreen 或杀毒软件可能对新下载、低信誉且涉及进程句柄
  的程序给出启发式提示。用户应从本仓库 Release 下载并核对 SHA-256。
- 静态清单与安装包位于同一 GitHub Release；启用不可变发布可防止发布后悄悄替换，但不能替代仓库账号
  安全。仓库维护者仍需启用强认证并谨慎保护发布权限。
- GitHub 服务不可达时无法在线检查；多开、退出和本地诊断等核心功能不受影响。
