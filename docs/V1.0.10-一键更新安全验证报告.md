# V1.0.10 一键更新与更名迁移验证报告

验证对象：`PascalePaF/wechat-wecom-duokai` V1.0.10  
验证范围：品牌资源、版本身份、覆盖安装、快捷方式迁移、一键更新、绿色版事务与回滚。

## 结论

V1.0.10 的变化集中在产品名称、Logo、主题资源、系统快捷方式迁移、版本号和文档。内部身份继续使用
`wechat_duokai`，没有扩大下载源、删除范围、进程控制、注册表路径或客户端访问范围。V1.0.9 安装版和
绿色版均可在原目录安全升级。

## 保持稳定的升级身份

- 主程序：`wechat_duokai.exe`
- Core：`WechatDuokai.Core.dll`
- 默认目录：`%LOCALAPPDATA%\Programs\WechatDuokai`
- 卸载登记：`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\WechatDuokai`
- 安装、绿色版、源码与数据目录标记值
- GitHub 仓库、Release URL、附件命名规则与更新计划协议

## 快捷方式迁移

安装或更新成功后创建“微窗助手”开始菜单和可选桌面快捷方式。随后只清理以下精确已知旧身份：

- V1.0.9：`开开助手.lnk` 与“开开助手”开始菜单目录中的主链接、完全卸载链接；
- V1.0.8 及更早：`微信企业微信多开助手.lnk` 与对应开始菜单目录中的两个链接。

只有旧开始菜单目录已经为空时才删除目录；若存在第三方或用户自己的额外文件，目录与额外文件均保留。
一键更新会在迁移前检查三代桌面快捷方式，用户原本有桌面入口时才生成新名称桌面入口。

## 更新信任链

1. 只从固定仓库的正式 GitHub Release 读取元数据。
2. 当前版本 `1.0.10` 与模拟下一版本 `1.0.11` 的比较、附件名称、规范 URL、大小和 digest 均有自动测试。
3. 下载 `SHA256SUMS.txt` 与精确版本 setup 后，GitHub digest、校验文件和本机文件三方 SHA-256 必须一致。
4. 最终校验至启动安装器期间保持文件不可写；安装器再次验证计划时效、父进程、目标目录和文件哈希。
5. 安装版与绿色版使用同卷暂存、逐文件备份和逆序回滚；`data` 不在替换清单中。
6. 品牌资源已嵌入主程序、setup 和 cleanup；自动测试比对安装器内嵌载荷与 Release 输出。

## 发布门禁

- Release x64 全量重建；
- 自动测试全部通过；
- 14 场景 UI 渲染并人工检查；
- 两次本地组包结果的正式发布文件 SHA-256 一致；
- GitHub Actions 全新 `windows-2022` 环境重建、复核 SHA-256、生成并验证 SPDX 2.2 SBOM；
- 对最终 CI 工件原件执行 Kaspersky 扫描并公开原始日志；
- 在同一源码提交创建 `v1.0.10` 标签后再公开 Release。

项目没有 Authenticode 代码签名。未知发布者或信誉类提示不能单独证明文件恶意或安全；用户应从正式
Release 下载并同时核对来源、标签、SHA-256、CI、SBOM、扫描日志和源码。
