# V1.0.8 一键更新安全验证报告

验证对象：`PascalePaF/wechat-wecom-duokai` V1.0.8  
验证日期：2026-09-19  
平台：Windows 10/11 x64、.NET Framework 4.8

## 1. 本版本变更对更新链的影响

V1.0.8 的功能变更限定在共享夜间主题资源、主界面入口整理、设置页诊断入口和相应自动回归。下载、校验、
安装交接、目录身份判断、事务替换和失败回滚代码沿用 V1.0.7 的安全设计。本版本同步更新产品版本、附件名、
安装器内嵌文档和自动化测试基线，避免旧版本文件名混入发布包。

## 2. 不变的信任链

1. 版本检查只读取 `PascalePaF/wechat-wecom-duokai` 的最新正式 GitHub Release 元数据；
2. 没有可信新版本时不显示一键更新按钮，也不下载附件；
3. 用户必须在确认框明确同意，程序才下载 `SHA256SUMS.txt` 和精确命名的 setup；
4. 初始 URL 必须是 HTTPS、GitHub、本仓库、目标标签和目标文件名；重名、缺失或异常路径均拒绝；
5. GitHub 为校验文件计算的摘要先验证 `SHA256SUMS.txt`；
6. GitHub setup 摘要、校验文件中的 setup 记录和下载文件 SHA-256 三方必须一致；
7. 下载位于 `data\updates`，有大小上限、字节数检查、临时扩展名和目录标记约束；
8. 从最终哈希到 Windows 成功启动 setup 期间保持文件不可写；
9. setup 再次核对自身哈希、版本、计划时效、父进程、目标目录和安装/绿色身份；
10. 文件在同卷暂存，逐项替换前备份，失败时按相反顺序恢复；`data` 不进入替换列表。

## 3. 网络与本地边界

启动检查或手动检查只允许读取 GitHub 公共 API。只有用户确认一键更新后，才读取同一正式 Release 的两个
附件。程序不上传窗口数量、用户名、客户端路径、账号、聊天内容、诊断或日志。GitHub 会看到普通 HTTPS
请求必需的 IP 地址和 User-Agent。

更新临时文件与结果分别位于：

```text
<程序目录>\data\updates\
<程序目录>\data\logs\update.log
```

安装版必须有 `.wechat-duokai-install`，绿色版必须有 `.wechat-duokai-portable`。身份缺失、冲突、路径为
重解析点或主程序结构不完整时，一键更新不可用；源码目录和普通文件夹不会被当作更新目标。

## 4. V1.0.8 自动回归

- 当前版本 `1.0.8` 与下一版本模拟值 `1.0.9` 的比较、附件名称和 URL 校验；
- 非 GitHub URL、嵌套路径、重复附件或重复校验记录拒绝；
- 安装版、绿色版、未标记目录和双身份目录识别；
- 人为在替换中断后完整恢复旧文件，并保持 `data\settings.ini`；
- 安装版/绿色版事务完成后文件版本为 `1.0.8`，清理器文件名与版本一致；
- 设置页的检查、一键更新、发布入口和诊断入口存在；主界面页脚不存在独立发布入口；
- 夜间颜色亮度与图标背景受自动断言约束；主题切换不改变更新信任边界。

正式发布还必须经过 GitHub Actions 全新 Windows Server 2022 构建、全部测试、SHA-256 逐项复核、SPDX 2.2
SBOM 生成与验证，并对下载回来的该次 CI 原始附件执行本机 Kaspersky 全文件扫描。扫描未检出只能作为一项
证据，不能构成绝对安全保证。

## 5. 限制与结论

项目没有 Authenticode 商业签名，因此 Windows 或安全软件可能显示未知发布者、低信誉或启发式提示。三方
哈希与事务回滚不能防御 GitHub 发布权限完全失守或本机当前用户会话已被恶意控制，但能阻止损坏、附件错配、
普通替换竞争和大多数半更新状态。

在这些边界内，V1.0.8 不静默下载或执行，不接受任意来源，不覆盖未标记目录，更新失败时优先保留或恢复
当前版本；本轮 UI 调整没有扩大网络、权限或文件删除范围。
