# 微窗助手 V1.1.2 版本说明

发布日期：2026-09-20

## 更新检查可承载更多用户

- 每个正式 Release 新增 `update-manifest.json`。客户端优先从 GitHub Release 静态附件读取最新版号、
  安装包名称、精确大小和 SHA-256，不再依赖未登录 REST API 才能完成检查或一键更新。
- GitHub API 只在发现新版本时作为可选的额外摘要核验。API 配额耗尽、限流或临时不可用，不会阻止
  用户发现、下载和校验正式版本。
- 保留 V1.1.1 及更早 Release 的兼容路径：若最新版还没有静态清单，继续通过普通 Release 跳转和
  固定附件地址检查。

## 降低请求高峰

- 自动检查成功后在安装目录 `data\update-state.ini` 缓存 24 小时；所有运行数据仍只保存在安装目录。
- 首次或到期的自动检查按当前安装目录产生稳定的 30–300 秒错峰延迟，不创建联网标识，也不上传
  安装目录或设备信息。
- 连续失败采用 1 小时、6 小时、24 小时退避，并识别服务器 `Retry-After`；最长不会超过 24 小时。
- 用户点击“检查更新”始终立即检查，不受自动检查缓存、错峰或退避限制。

## 更新安全

- 静态清单只接受固定仓库、固定 HTTPS 域名、规范标签路径、精确附件名、大小上限和有效 SHA-256。
- 下载 `SHA256SUMS.txt` 后，先验证其 SHA-256，再验证其中唯一的 setup 记录，最后复算下载文件摘要。
- API 可用时，服务端附件摘要还必须与静态清单一致；发现任何元数据冲突都会停止一键更新。
- 安装仍必须由用户在确认框中主动同意；本版没有静默下载、静默覆盖或后台自动安装。

## 发布完整性

- GitHub Actions 在全新 Windows Server 2022 环境构建、测试、复核 SHA-256、验证静态清单并生成
  SPDX 2.2 SBOM。
- 从 V1.1.2 开始启用 GitHub Immutable Releases：正式发布后标签和附件不可替换，发布前使用草稿
  一次性上传全部附件。

完整设计与威胁边界见 `V1.1.2-一键更新安全验证报告.md` 和 `V1.1.2-全项目自查报告.md`。
