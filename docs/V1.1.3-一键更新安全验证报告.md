# V1.1.3 一键更新与代理兼容安全验证报告

文档编号：`WD-V113-UPDATE-PROXY-20260920`

## 1. 现场问题

正式发布 V1.1.2 后，以真实 .NET Framework 4.8 进程访问已发布的静态清单。现场同时满足：

- 进程环境含 `HTTPS_PROXY=http://127.0.0.1:7897`；
- WinHTTP 为 Direct；Windows Internet Settings 的 `ProxyEnable=0`；
- 浏览器、PowerShell 7 和 curl 能经环境代理访问 GitHub；
- .NET Framework 默认 `HttpClientHandler` 未能稳定采用该环境代理，静态清单 GET 超时或 TLS 失败。

这不是 API 配额、清单错误、病毒拦截结论或 GitHub 附件损坏，而是旧框架与环境代理的兼容边界。

## 2. 修复设计

新增统一 `NetworkProxyPolicy`，由版本发现和附件下载共同使用：

1. 优先读取非空 `HTTPS_PROXY`，否则读取 `HTTP_PROXY`；未设置或不合法时保留 Windows 默认代理行为。
2. 代理 URI 只允许绝对 `http` / `https`、有效主机和端口、根路径；拒绝 query、fragment、文件 URI
   与额外路径，避免把路径或参数误当成代理配置。
3. URI user-info 可转换为 `NetworkCredential` 配置给 `WebProxy`；不写文件、不显示、不记录。
4. GitHub 请求固定 TLS 1.2；不允许回退到 SSL 3.0、TLS 1.0 或 TLS 1.1。
5. `latest/download/update-manifest.json` 使用 HEAD 取得规范版本跳转，随后才 GET 最多 64 KiB 的清单。
6. setup 和 SHA256SUMS 下载使用同一代理策略，最终响应 URI仍必须属于 GitHub 官方交付域。

代理只改变传输路径，不改变可信仓库、标签、附件名、大小、摘要或执行策略。即使本地代理进行 HTTPS
扫描，下载文件仍必须与不可变 Release 静态清单、SHA256SUMS 和可选 GitHub digest 一致。

## 3. 自动回归

- 接受规范 `http://user:password@127.0.0.1:7897` 并正确解码代理凭据。
- 拒绝 `file://`、带路径和带 query 的代理地址。
- 静态清单测试确认第一步 HEAD 跳转，API 403 时仍可一键更新。
- 原有恶意外域、嵌套附件路径、重复附件、无效摘要、24 小时缓存、错峰、退避和事务回滚测试保持通过。

## 5. 安全边界

- 环境变量属于启动进程的本机配置。若恶意本地程序已经能修改目标进程环境或安装受信任根证书，它本来
  就处于较高本机权限边界；本项目不会尝试绕开用户选择的安全代理。
- 代理凭据不会进入诊断、更新状态、User-Agent 或错误文案。
- 自动安装仍需用户确认；代理兼容不允许静默下载、静默执行或放宽哈希。
- V1.1.2 已是不可变 Release，不能原地替换；修复以新版本 V1.1.3 发布并保留完整历史证据。
