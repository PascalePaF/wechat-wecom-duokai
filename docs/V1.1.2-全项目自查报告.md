# 微窗助手 V1.1.2 全项目自查报告

文档编号：`WD-V112-AUDIT-20260920`

## 结论

本次变更集中在更新发现、请求调度、发布完整性和对应测试，没有扩展微信/企业微信数据访问范围，没有
加入账号、消息、聊天记录或诊断上传。联网目标仍限定为本项目 GitHub Release、GitHub 官方附件交付域，
以及发现新版本时可选访问的固定 GitHub API。

## 架构检查

| 模块 | V1.1.2 变化 | 边界 |
| --- | --- | --- |
| `ReleaseUpdateChecker` | 静态清单优先；旧 Release 兼容；API 仅作摘要增强 | 固定 HTTPS 主机、路径、版本、名称、大小和 SHA-256 |
| `UpdateCheckSchedule` | 24 小时缓存、30–300 秒错峰、1/6/24 小时退避 | 状态仅写安装目录 `data`；损坏状态失败开放 |
| `ApplicationUpdateService` | 同时核对清单摘要、SHA256SUMS 和下载文件 | 未通过校验的 EXE 永不执行 |
| `MainWindow` | 自动检查按调度运行；手动检查仍即时 | 更新前继续弹出明确确认框 |
| 构建脚本 | 生成 `update-manifest.json` | 清单在所有二进制和 SHA256SUMS 完成后产生 |
| GitHub Actions | 解析并重算清单中的三个发布附件 | 全新 Windows 环境，随后生成/验证 SPDX 2.2 SBOM |

## 数据与隐私

新增文件 `data\update-state.ini` 只保存：上次尝试时间、上次成功时间、下次允许的自动检查时间、连续失败
次数和最近版本号。错峰值从本地安装路径单向计算，但不保存路径、不发送路径，也不形成跨安装可用的远程
标识。程序没有遥测、崩溃上传、自动日志上传、广告 SDK、分析 SDK、远程配置或后台常驻服务。

## 安全敏感能力复核

- 微信多开仍只处理腾讯客户端的已知互斥体；不读取账号、聊天数据库或凭据。
- 企业微信扩展仍使用短期注册表事务和精确互斥体策略；崩溃恢复与外部冲突保护保持不变。
- “退出全部”仍限定当前 Windows 会话和经过签名/路径验证的准确客户端进程。
- 更新下载仍写入当前程序的 `data\updates`，目录身份不明时禁止自动覆盖。
- 没有新增 DLL 注入、远程线程、键盘钩子、屏幕采集、系统启动项、计划任务或防火墙例外。

## 兼容与故障模式

- V1.1.2 能识别以后带静态清单的 Release；最新版为 V1.1.1 或更早时自动使用兼容路径。
- API 限流不会再造成“无法检查更新”，只会失去一层可选 GitHub 服务端摘要交叉核验。
- 静态清单缺失时可进入 V1.1.1 的固定 Release/SHA256SUMS 兼容路径；清单一旦存在但格式错误、URL
  越界、摘要冲突或附件超限，就会失败关闭一键更新，用户仍可查看发布页。
- 本地状态文件不可读/不可写时，不影响手动检查和核心多开；自动检查按首次运行处理。
- 自动检查在窗口显示后异步等待，不阻塞界面；关闭程序会取消等待。

## 验证清单

- 解决方案 Release 编译与自动测试。
- 静态清单解析、恶意 URL 拒绝、API 403 降级和旧版兼容回归。
- 自动检查缓存、错峰、退避、Retry-After 与损坏状态回归。
- 发布包 SHA-256、静态清单和 SPDX 2.2 SBOM 的 CI 验证。
- 正式 CI 附件在发布前执行 Kaspersky 全目录扫描，并保留原始扫描日志。

## 仍需公开的限制

项目不含商业代码签名，启发式安全软件可能根据“未签名 + 进程句柄/注册表 + 新文件信誉低”告警。扫描
结果只能说明当时的样本与病毒库未发现已知威胁，不能证明绝对安全。企业微信多开仍受腾讯具体版本内部
实现影响，未来官方版本改变互斥体或注册表行为时应停止强行兼容并重新验证。
