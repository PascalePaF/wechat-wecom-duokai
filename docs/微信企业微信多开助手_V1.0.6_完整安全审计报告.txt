微信 · 企业微信多开助手 V1.0.6 完整安全审计报告

文档编号：WD-SA-2026-09-16-V106
审计日期：2026-09-16（Asia/Tokyo）
审计对象：PascalePaF/wechat-wecom-duokai V1.0.6 源码、构建脚本和候选发布文件

一、结论

本次源码审计没有发现后台上传聊天记录、联系人、账号、凭据、文件、诊断或恢复日志的实现；没有发现
远程控制、键盘记录、截屏、静默下载执行、开机自启、DLL 注入、客户端文件篡改或隐藏加密载荷。

V1.0.6 的联网边界与 V1.0.5 相同：仅在用户开启启动检查或主动点击检查时，向 GitHub 公开 API 读取
本项目最新 Release 的版本号；不下载附件、不执行更新、不上传本地资料。下载入口只调用系统浏览器。

二、V1.0.6 新增持久文件

所有持久运行文件都位于主程序所在目录的 data 子目录：

- data\settings.ini：微信目标、企业微信目标、版本检查偏好、自选客户端路径；
- data\theme.ini：主题偏好；
- data\diagnostics\diagnostic-*.txt：用户主动生成的本地诊断；
- data\recovery\wecom-registry-transaction.ini：仅在企业微信临时注册表事务未结束时存在；
- data\logs\registry-recovery.log 和最多一份 .1：恢复结果审计。

程序不再向 %LOCALAPPDATA%\WechatDuokai 创建新的运行文件。升级时只迁移带本项目专用标记的旧目录中
settings.ini 和 theme.ini，成功后删除旧文件。data 拒绝目录联接/符号链接；安装目录不可写时停止启动，
不会悄悄回退到其他位置。

开始菜单、桌面快捷方式和 HKCU 卸载登记是 Windows 安装集成项，不是运行数据。清理器为删除自身会在
系统临时目录建立短期工作副本，并使用 MoveFileEx 安排自删除。

三、注册表断电恢复安全性

修改 HKCU\SOFTWARE\Tencent\WXWork\multi_instances 前，程序记录：随机事务号、时间、PID、进程启动
时间、固定路径和值名、原始存在性/类型/值、预期临时状态。日志先写同目录临时文件，使用 WriteThrough
和 Flush(true) 落盘，再原子改名，最后才修改注册表。

下次启动仅在以下条件恢复：旧事务目标严格等于固定的策略路径和值名；旧所有者不再运行；当前注册表
存在性、RegistryValueKind 和值全部等于预期临时状态。当前状态不匹配时认定第三方已修改并保留当前值。
日志损坏或目标不匹配时隔离日志且不写注册表；隔离文件存在期间阻止新的临时注册表会话，避免在未知
状态上继续叠加修改。

支持缺失值、DWORD、QWORD、字符串、可扩展字符串、多字符串和二进制。Base64 只是文本序列化，不是
加密。恢复审计不写原始值，只写事务号、结果和原因，并在 256 KiB 后轮换，避免无限增长。

四、剩余边界

1. Windows 普通注册表值不提供跨进程 compare-and-swap。第三方仍可能在最后比较和恢复写入之间竞争；
   命名信号量只能协调本助手实例。
2. 文件 Flush(true) 显著降低断电丢失事务的概率，但不能对故障磁盘、控制器缓存或文件系统损坏作绝对
   保证。
3. 同一用户账户下的恶意程序本来就能修改 HKCU 和用户可写文件；恢复日志用于故障恢复和防误覆盖，
   不是抵御已控制账户的密码学边界。
4. 多开仍使用进程枚举、已知锁白名单和企业微信短期 HKCU 兼容状态，可能被启发式安全模型关注。
5. 发布文件未使用受公共信任的 Authenticode 证书，可能出现未知发布者或信誉提示。

五、自动化证据

- 独立保存微信 7、企业微信 4，重载后互不覆盖；
- 正常双开、扩展模式恢复原始存在性、值和类型；
- 第三方把临时 DWORD 2 改成其他 DWORD 时，正常结束和崩溃恢复都保留第三方值；
- 子测试进程建立事务后不调用 Dispose 直接退出，父进程模拟下一次启动并恢复；
- 扩展模式崩溃后精确恢复 REG_MULTI_SZ 的内容、顺序和类型；
- 正常恢复和已处理冲突不遗留活动事务；
- 审计日志不包含测试使用的原始字符串；
- 所有持久路径均位于程序目录，安装测试确认 data 标记；
- 原有签名验证、路径过滤、根实例统计、补开、安装覆盖、卸载保护和 UI 回归继续通过。

六、文件删除与卸载

安装目录本身通过专用标记、结构、精确路径和 ReparsePoint 检查后才可递归删除；data 随安装目录一并
删除。清理器仍可选择保留源码或在额外勾选、结构校验和最终确认后删除源码。它不结束微信/企业微信，
只关闭位于已验证程序/源码/绿色目录中的本工具进程。

七、恶意与隐私代码复核

未发现以下代码或数据流：聊天数据库访问、账号/Cookie/Token 搜索、环境变量批量采集、键盘/屏幕捕获、
任意文件上传、远程命令、PowerShell 下载、动态脚本、反射加载网络程序集、启动项/计划任务、驱动安装。

可见网络地址仍只有本项目 GitHub API/Release。可见原生调用用于窗口外观、进程/句柄兼容、签名验证、
快捷方式和清理器自删除；没有网络套接字或注入 API 链。

八、发布门禁

正式发布必须由 GitHub Actions 全新 Windows 环境重新构建，执行完整测试、生成 SHA-256 和 SPDX 2.2
SBOM，再对最终决定上传的确切附件执行本机 Kaspersky 全文件扫描。扫描报告单独附在同版本 Release，
包含病毒库日期、检测、可疑、跳过、损坏和错误数。任何明确检测都应先隔离调查，不建议盲目忽略。

九、最终意见

V1.0.6 源码没有发现恶意或隐私上传实现。新增恢复日志改善了异常中断后的注册表可恢复性，同时保留
第三方冲突优先规则；自包含 data 目录使用户更容易审查、备份和完整删除运行数据。该结论不是绝对安全
保证，仍需结合公开源码、提交标签、正式附件哈希、SBOM、CI 结果和最新安全软件扫描共同判断。
