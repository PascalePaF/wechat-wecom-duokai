   远程控制、静默下载、开机自启、代码注入或隐藏载荷的证据。

2. 2026-09-12 23:43 的卡巴斯基告警真实发生，名称为：

   VHO:Trojan.Win32.Convagent.gen
   分类：木马
   级别：高
   检测方法：启发式分析
   来源：云保护

3. 这条告警不能直接忽略，但也不能只凭名称认定程序上传了聊天记录。源码和反编译代码
   中没有网络上传实现，也没有聊天、账号、浏览器凭据等数据采集入口。后续当前构建的
   卡巴斯基强制扫描为 0 检测、0 可疑。

4. 最准确的判断是：这是一条没有被其他证据证实的通用启发式/云端判定，误报可能性较高；
   但只有 Kaspersky 病毒实验室能对它作正式误报裁定。本报告不会把“可能误报”写成
   “百分之百误报”。

5. 当前总体风险为中等：恶意代码和隐私上传证据未发现，但程序尚未代码签名，使用了
   Windows 句柄枚举/关闭技术，而且本机卡巴斯基病毒库提示过期、在线更新又因 TLS
   错误失败。这些限制都必须公开。

三、原开源项目是否上传隐私

上游源码实际只做以下事情：

1. 从当前用户注册表读取微信、企业微信安装路径；
2. 给企业微信当前用户注册表写入 multi_instances；
3. 按用户输入数量启动微信或企业微信；
4. 用户主动点击界面链接时打开作者网站；
5. 用 WinForms 计时器连续发送启动请求。

上游全部源码中没有发现：

- HttpClient、WebClient、WebRequest、Socket、TCP、UDP、WebSocket、FTP 或上传/下载调用；
- 读取微信聊天数据库、消息、账号、Cookie、浏览器密码、Windows 凭据库或用户文档；
- 剪贴板、键盘钩子、屏幕抓取、摄像头、麦克风；
- Run/RunOnce、计划任务、服务、驱动等开机持久化；
- PowerShell、cmd.exe、隐藏脚本或动态程序集加载；
- DLL 注入、远程线程、写进程内存或客户端二进制补丁；
- 加密配置、硬编码控制服务器、API 密钥或访问令牌。

上游项目文件虽列有未使用的 System.Net.Http 框架引用，但源码没有调用，编译后的程序集
引用表也没有 System.Net.Http。一个未使用的引用本身不能执行联网。

结论：没有证据表明原开源源码会后台上传隐私。这个结论不覆盖被第三方替换过的同名 EXE，
也不对未来未知提交作保证。

五、为什么新版本容易触发启发式告警

为了实现“开了 3 个，误关 1 个后只补回 1 个”，程序必须在仍有微信运行时解除单实例锁。
当前代码使用：

- NtQuerySystemInformation 枚举系统句柄；
- OpenProcess，仅申请 PROCESS_DUP_HANDLE；
- DuplicateHandle 复制句柄并读取名称；
- DUPLICATE_CLOSE_SOURCE 只关闭匹配白名单的单实例锁；
- 对微信 4.x 只匹配当前用户精确路径
  %APPDATA%\Tencent\xwechat\lock\lock.ini。

这不是 DLL 注入，不写微信内存，不终止微信，也不修改微信程序文件。但是句柄枚举、关闭其他
进程中的锁、自删除清理器和未签名新哈希，确实与安全软件重点监控的一些技术表面相似，容易
触发信誉或启发式模型。

Microsoft 也明确提示 NtQuerySystemInformation 属于可能在未来 Windows 版本改变或不可用的
内部接口。因此这里既有误报风险，也有兼容性风险。

六、本轮已经收紧的代码

1. 微信/企微进程路径读取失败时，直接跳过，不再只凭同名 EXE 接受；
2. rundll32 兼容候选只能匹配精确 lock.ini 文件路径，绝不按微信互斥锁名称处理；
3. 只有 DuplicateHandle 真实关闭成功才计数；
4. 所有操作只限当前 Windows 登录会话；
5. 不申请调试权限，不提权，不终止微信/企微；
6. 所有递归删除根目录统一拒绝目录联接和符号链接；
7. 清理过程逐层删除，遇到链接只删除链接本身，不进入目标目录；
8. 清理计划必须与当前清理工作进程和计划文件路径一致；
9. 发布脚本清理旧产物前也拒绝目录联接；
10. 相同源码连续 Release 构建的主程序和安装器哈希完全一致。

七、安装与完全卸载风险

程序只写入：

- 用户选择并通过校验的专用安装目录；
- %LOCALAPPDATA%\WechatDuokai 下的数量和主题设置；
- 当前用户开始菜单与可选桌面快捷方式；
- HKCU 当前用户卸载登记；
- 企业微信当前用户 multi_instances 配置。

主程序和安装器都以 asInvoker、uiAccess=false 运行，不静默要求管理员权限。

完全卸载使用不同标记分别识别源码、安装、发布、绿色包和用户设置，还要求目录结构匹配。
它拒绝磁盘根目录、系统关键目录、目录联接、源码/发布目录作为安装目标，以及没有标记的
非空目录。“删除源码”默认不选中，必须额外勾选并再次确认。

仍需说明：这些公开标记是防误删措施，不是密码。已经完全控制同一 Windows 用户账户的
攻击者本来就能删除用户有权访问的文件，标记不能抵御这种攻击者。完全删除源码也会删除
没有推送的本地修改，因此使用前必须确认 Git 已同步。

九、“高危、启发式、云监测”的正确理解

高危：表示如果判定为真，潜在后果严重；它不是检测置信度 100%。

启发式分析：不一定命中已知恶意样本的精确签名，而是代码结构、指令组合或行为特征类似
威胁。Kaspersky 官方将这类对象描述为“可能感染”，并明确承认非感染代码与病毒相似时会
发生误报。

云监测/云保护：KSN 云端信誉、机器学习或快速更新知识库参与判断。新生成、未签名、缺少
下载信誉的文件更容易产生波动。

Convagent.gen：gen 是通用/泛化判定。审计时没有在 Kaspersky 官方威胁百科找到能把这个
名称唯一对应到本项目具体恶意行为的条目，不能仅凭这个名字推断“上传聊天记录”。

只有 Kaspersky 病毒实验室能正式确认误报。后续零检出和源码证据支持“误报可能性较高”，
但本报告不会越过厂商实验室下最终结论。

十、病毒库和扫描限制

本次 Kaspersky 日志显示完整病毒库日期为 2026-09-11 00:57:00，但产品事件持续提示
“数据库已过期”。主动更新时多个 Kaspersky 更新节点均发生 TLS 错误，Updater 状态为 failed；
系统 HTTPS 测试也发生 TLS 握手失败。

因此：0 检测是有价值的证据，但不是“使用最新病毒库扫描”的证据。网络/TLS 恢复后必须先
成功更新，再进行一次扫描。Microsoft Defender 当前因 Kaspersky 接管而禁用，也没有提供
第二款本机引擎的证据。

十二、剩余风险

中风险：发布文件未签名，每个新哈希需要重新建立信誉，无法向用户证明发布者身份。

中风险：NtQuerySystemInformation 是内部接口，Windows 或腾讯客户端升级后可能失效。

低至中风险：客户端路径来自注册表、运行进程和常见目录；同一用户账户已被控制时，攻击者
可能放置同名 EXE。下一版本应验证腾讯 Authenticode 签名。

低风险：企业微信 multi_instances 值会保留。下一版本应保存并恢复原值。

中风险：完全删除源码会造成未提交修改永久丢失；必须先推送 GitHub。

中风险：多开是客户端兼容技巧，可能带来登录冲突、账号策略或企业组织规则风险。

十三、是否建议运行

个人本机测试：在只从本项目 Release 下载、核对 SHA-256、最终扫描为 0 检测、不关闭安全
软件并理解多开风险的前提下，现有证据支持测试。首次建议使用非关键账号。

企业或大规模分发：代码签名、最新病毒库复扫、第二款独立引擎、Kaspersky 实验室正式裁定、
腾讯客户端签名验证完成前，不建议作为企业级可信软件大规模部署。

十四、下一步建议

最高优先级：
- 使用受信任 Authenticode 证书签名主程序、安装器和清理器，并加 RFC 3161 时间戳；
- 修复本机网络/TLS 后更新 Kaspersky 病毒库并复扫；
- 将告警样本和事件日志提交 Kaspersky 病毒实验室裁定；
- Release 同时公开源码提交、SHA256SUMS.txt、扫描日志和本报告。

下一版本：
- 启动前验证微信/企业微信文件签名和腾讯发布者；
- 保存并恢复企业微信 multi_instances 原值；
- 把句柄解除放入显式“高级兼容模式”；
- 调查腾讯官方多开参数/API，存在官方方案时替换内部 NT API；
- 增加干净环境 CI、SBOM、可复现构建证明和第二引擎扫描。

十五、最终意见

原开源源码上传隐私：未发现证据。
旧版 EXE：未发现后门，但不可复现、未签名，不建议继续分发。
卡巴斯基告警：真实发生，但尚未被证实为真实木马，误报可能性较高。
当前 V1.0.1：未发现恶意链条，敏感操作和卸载范围已经进一步收紧。
绝对安全承诺：不能提供；未签名、内部 NT API、病毒库过期和缺少第二引擎仍是剩余风险。
