# 微窗助手 V1.1.1 一键更新安全验证报告

文档编号：`WC-UPDATE-2026-09-20-V111`

## 1. 事件与根因

用户在 V1.0.11 设置页点击“检查更新”后得到统一失败提示。现场请求返回：

- HTTP 状态：`403 rate limit exceeded`
- 未登录核心 API 上限：`60`
- 剩余次数：`0`
- 复位时间：`2026-09-20 14:03:08 +09:00`

同一时刻，DNS、GitHub 普通 Release 页面和正式附件均可访问。因此根因不是病毒、仓库删除、DNS 故障、
证书故障或 Kaspersky 拦截，而是旧检查器把每次启动/手动检查都直接发送到 GitHub 未登录 REST API，
并在收到 403 后丢弃了具体错误。

## 2. 修复后的协议

1. 对固定地址 `https://github.com/PascalePaF/wechat-wecom-duokai/releases/latest` 发送 HEAD。
2. 只接受 HTTPS、`github.com`、无查询/片段且路径精确为本仓库 `/releases/tag/v<版本>` 的跳转。
3. 若版本不高于本机版本，立即结束，不访问 REST API。
4. 若发现新版本，尝试读取固定仓库的 GitHub API 元数据以取得服务端生成的附件 digest。
5. API 非成功、超时或连接失败时，不把版本检查判为失败；改为对精确版本 setup 与
   `SHA256SUMS.txt` 发送 HEAD。
6. 附件只接受固定仓库/标签/名称的 HTTPS URL，最终交付地址必须仍为 `github.com` 或
   GitHub 控制的 `*.githubusercontent.com`，大小必须大于 0 且低于本地上限。
7. 用户确认后才下载正文；更新文件仍限制在当前程序目录的 `data\updates`。

## 3. 校验模型

| 情况 | 执行前必须满足 |
| --- | --- |
| API 可用 | GitHub digest = `SHA256SUMS.txt` = 本机下载文件 SHA-256 |
| API 不可用 | 固定 HTTPS Release 地址与大小约束；`SHA256SUMS.txt` 中必须且只能有一条目标 setup；清单 SHA-256 = 本机下载文件 |

API 降级不会绕过安装目录标记、下载上限、清单唯一性、文件锁、启动前复算、更新计划时效、父进程身份、
暂存备份或回滚检查。没有代码签名的现实限制也没有被隐藏；用户仍应核对仓库、标签和发布哈希。

## 4. 自动验证

- API 403 / 配额为 0 时，检查结果仍为成功并发现下一版本。
- 降级模式能够取得精确 setup 和 `SHA256SUMS.txt` 大小，并允许进入确认式更新流程。
- 非 GitHub 最新版跳转、带查询或无法解析的版本地址被拒绝。
- API 返回的非本仓库附件、嵌套路径、重复附件和无效 digest 继续被拒绝。
- 相同版本只访问配额无关的 Release 跳转，不消耗 API 次数。
- 用户取消、网络超时与窗口关闭使用不同分支；HttpClient 超时会显示错误，不再静默停在“正在检查”。

## 5. 现场复验

在未登录 API `X-RateLimit-Remaining: 0` 的真实现场，使用 .NET Framework 4.8 修复版检查器对
V1.0.11 执行检查，结果为：

- `CheckSucceeded=True`
- `IsUpdateAvailable=True`
- `LatestVersion=1.1.0`
- `CanInstallUpdate=True`
- `HasGitHubAssetDigests=False`（按预期进入清单降级模式）
- setup：`wechat_duokai-setup-v1.1.0.exe`，761,856 字节
- 清单：`SHA256SUMS.txt`，580 字节

该结果直接证明本次修改覆盖了用户遇到的状态，而不只是模拟成功路径。
