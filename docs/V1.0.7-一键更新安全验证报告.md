# V1.0.7 一键更新安全验证报告

验证对象：`PascalePaF/wechat-wecom-duokai` V1.0.7
验证日期：2026-09-16
平台：Windows 10/11 x64、.NET Framework 4.8

## 1. 目标

本版本允许用户在程序设置页检查并一键安装新版本，同时保持以下边界：

1. 未经用户确认不下载、不执行；
2. 只信任本项目公开 GitHub Release；
3. 传输损坏、附件替换或校验信息冲突时停止；
4. 不把安装版误改成绿色版，也不把绿色版转换成安装版；
5. 不覆盖普通目录、源码目录或用户的 `data`；
6. 覆盖失败时恢复旧程序文件。

## 2. 更新顺序

1. 向 GitHub 公共 REST API读取最新正式 Release 元数据；
2. 严格解析版本号、Release 页面、附件名称、状态、大小、下载 URL 和 GitHub `digest`；
3. 下载 `SHA256SUMS.txt`，先用 GitHub 为该附件计算的摘要验证它本身；
4. 从校验文件中取得唯一一条目标 setup 记录；重复、缺失或路径不匹配均拒绝；
5. 要求校验文件中的 setup 哈希等于 GitHub setup `digest`；
6. 将 setup 下载为 `data\updates\*.part`，限制最大体积并验证实际字节数；
7. 计算下载文件 SHA-256，要求与前两项一致后才改名为 `.exe`；
8. 写入强制落盘的更新计划；
9. 保持安装包只读锁，从最终哈希计算连续到 Windows 成功启动安装程序，避免启动前被替换；
10. 独立安装程序再次验证自身路径、哈希、版本、计划时效、父进程和目标目录标记；
11. 当前程序退出后，把新文件释放到 `data\updates\staging-*`；
12. 逐项替换时把旧文件保存到 `backup-*`；任何一步失败都按相反顺序恢复；
13. 成功后刷新必要的安装集成并重新启动主程序。

## 3. 允许的网络行为

自动检查开启时：

- `GET https://api.github.com/repos/PascalePaF/wechat-wecom-duokai/releases/latest`

只有用户确认一键更新后：

- 下载同一 Release 的 `SHA256SUMS.txt`；
- 下载名称严格为 `wechat_duokai-setup-v<目标版本>.exe` 的附件；
- GitHub 可以把附件请求重定向到其官方 Release 资源主机。

程序不上传设备信息、用户名、客户端路径、聊天记录、账号、诊断报告或更新日志。GitHub 作为服务端会看到
普通 HTTPS 请求所必需的网络元数据，例如 IP 地址和 User-Agent。

## 4. 本地文件边界

更新临时内容全部位于：

```text
<程序目录>\data\updates\
```

更新结果日志位于：

```text
<程序目录>\data\logs\update.log
```

计划、下载、暂存和备份目录都必须位于带有效用户数据标记的 `data` 下，且不能是符号链接或目录联接。
安装程序仅替换白名单中的程序文件；它不会把 `data` 加入替换列表。

## 5. 安装版与绿色版

- 安装版必须存在 `.wechat-duokai-install` 标记；更新后刷新开始菜单和卸载登记。
- 绿色版必须存在 `.wechat-duokai-portable` 标记；只原地更换程序和随包文档。
- 同时存在两个身份标记、缺少标记、主程序缺失或目录为重解析点时，一键更新不可用。
- 绿色版目录可以由用户重命名；身份依赖专用标记和文件结构，而不是文件夹显示名称。

## 6. 自动化验证

V1.0.7 自动化测试新增并覆盖：

- 完整 GitHub Release JSON 与附件摘要解析；
- 非 GitHub 下载地址拒绝；
- 重复 setup 哈希记录拒绝；
- 未标记、安装版、绿色版和双身份目录识别；
- 事务更新成功后主程序版本正确；
- 人为在第二个文件替换后抛出异常，确认全部旧文件恢复；
- 成功更新和失败回滚都不改变 `data\settings.ini`；
- 设置页一键更新按钮在可信新版本出现前保持隐藏。
- V1.0.6 的两个目标数按确定规则合并为一个，并删除旧配置字段；两个客户端共用同一控件。

正式发布还必须经过 GitHub Actions 全新 Windows Server 2022 构建、全部测试、发布哈希复核、SPDX 2.2
SBOM 生成与验证，以及对该次 CI 原始附件执行的本机卡巴斯基扫描。

## 7. 限制与结论

三方哈希与事务回滚可以防止传输损坏、附件错配、普通替换竞争和多数半更新状态，但不能代替代码签名，
也不能防御已经完全控制 GitHub 仓库发布权限或已经控制本机当前用户会话的攻击者。当前项目仍未签名，
因此 Windows 或安全软件可能显示信誉提示。

在上述边界内，V1.0.7 的一键更新不会静默执行，不接受任意 URL，不覆盖未标记目录，并在失败时优先恢复
旧版本；其安全性明显高于“下载后直接运行”的简单更新方式。
