# V1.1.5 一键更新安全验证报告

文档编号：`WD-V115-UPDATE-20260922`

## 1. 目标与结论

V1.1.5 在保留用户确认式安装的前提下，增加可选“发现后自动下载并校验”和已验证缓存复用。自动下载
不等于自动执行：独立安装程序仍只在用户点击安装、阅读确认框并同意后启动；启动前还会再次读取并计算
本机 setup 哈希。

结论：没有把网络元数据直接变成可执行信任，也没有因减少重复下载而降低摘要、目录或事务边界。

## 2. 版本发现链

1. 首选固定仓库的 `releases/latest/download/update-manifest.json`，不消耗公共 REST API 配额。
2. 只接受 GitHub 规范版本标签、固定仓库 Release 页面和规范附件 URL。
3. 清单限制为 64 KiB；setup 限制为 20 MiB；校验文件限制为 256 KiB。
4. GitHub API 可用时，版本、名称、大小和服务端 digest 必须与静态清单一致。
5. API 限流、超时或共享出口配额耗尽时，静态清单主路径仍可工作；元数据发生冲突则关闭一键更新。
6. 手动检查立即执行；自动检查使用 24 小时成功缓存、30–300 秒稳定错峰与 1/6/24 小时失败退避。

## 3. 自动下载与缓存复用链

自动下载开关默认关闭。启用后，仅在发现更高正式版本、附件齐全且当前目录具有安装版或绿色版专用标记
时准备更新包。下载和复用均写入当前程序目录 `data\updates`。

缓存只有满足以下全部条件才会复用：

1. 静态清单或 GitHub API 已提供可信的 `SHA256SUMS.txt` 与 setup 摘要；旧版无外部摘要模式不复用。
2. 本地校验文件和 setup 的长度分别精确等于 Release 元数据，且不超过硬上限。
3. 本地校验文件 SHA-256 等于可信 Release 摘要。
4. 校验文件中必须且只能有一条目标 setup 记录。
5. 该记录的 setup SHA-256 等于可信 Release 摘要。
6. 本机 setup 的实际 SHA-256 等于上述记录。

任何一步失败都不会执行缓存；程序只尝试删除这一版本精确命名的校验文件和 setup，然后走完整可信下载。
其他目录、其他版本和未知文件不在清理范围。

## 4. 安装执行链

1. 设置中的自动下载只把按钮变为“安装 Vx”，不会启动 EXE。
2. 用户点击后显示版本、安装版/绿色版模式、大小、校验级别和数据保留说明。
3. 用户拒绝时不执行文件；已验证缓存可以保留，之后再次安装仍会复核。
4. 用户同意后，主进程用只读共享限制打开 setup，并重新计算 SHA-256。
5. 只允许 `data\updates` 中与准备记录一致的文件；随后写穿保存带事务 ID 的更新计划。
6. 独立安装程序核对父进程身份、标记目录、版本、哈希和计划路径，执行同卷暂存、逐文件备份与回滚。

## 5. 网络、隐私与故障处理

- 只访问本项目 `github.com`、`api.github.com` 和 GitHub 官方 Release 交付域。
- 使用 TLS 1.2；规范 `HTTPS_PROXY` / `HTTP_PROXY` 可由当前进程采用，但不写入设置、诊断或日志。
- 自动下载失败不会影响多开功能，也不会把检查成功错误记成版本发现失败；用户可以手动重试或打开发布页。
- 设置只保存布尔偏好；不保存 GitHub 令牌、设备标识、账号、聊天、联系人或遥测。
- 下载缓存超过保留期后只按已知文件名前缀清理；被锁定文件留待下次处理，不扩大删除范围。

## 6. 回归与发布门禁

- 自动测试覆盖静态清单、API 403 回退、规范域名、大小上限、重复校验记录、错峰/退避和代理 URI。
- V1.1.5 新增“完整缓存成功复用”和“同长度内容篡改后拒绝并清理”回归。
- 本机 Release 重建与完整测试；全新 GitHub Windows Server 2022 重建；SHA256SUMS、静态清单和
  SPDX 2.2 SBOM 复核；最终 CI 原件执行 Kaspersky 扫描；草稿附件服务端摘要一致后才发布不可变 Release。

最终判断：可选自动下载提高了可用性，安装授权、摘要验证、执行目录、独立身份和事务回滚边界未放宽。
