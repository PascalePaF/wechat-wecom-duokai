微窗助手 V1.0.11 完整安全审计报告
====================================

报告日期：2026-09-19（Asia/Tokyo）
审计对象：PascalePaF/wechat-wecom-duokai V1.0.11 源码、构建脚本、Shell 集成、更新链与候选发布文件

一、结论摘要
------------

未发现后台上传聊天、账号、联系人、凭据、诊断或本地路径的代码；未发现 DLL 注入、远程线程、客户端
文件修改、键盘记录、屏幕抓取、持久化服务、计划任务、隐藏驱动或任意远程命令执行链。

V1.0.11 的新增代码用于：显式窗口图标、稳定 AppUserModelID、Windows Shell 图标刷新通知、版本号单一来源、
发布一致性门禁、不可恢复 UI 异常后的有序退出，以及相应自动测试。未增加隐私权限或新的网络端点。

二、任务栏图标问题
------------------

V1.0.10 的 app/setup/cleanup EXE 均已包含新的绿蓝 ICO，问题不是“打包进了旧图”。根因是 WPF 窗口未显式绑定图标、
进程缺少稳定 Shell 身份，且覆盖同路径后 Explorer 可以继续使用旧缓存。

V1.0.11 已对三个 WPF 窗口设置同一 AppIcon Resource；主程序、安装器、清理器分别使用独立 AppUserModelID；
桌面与开始菜单快捷方式通过 IPropertyStore 写入与目标进程一致的 System.AppUserModel.ID；
安装、更新、运行和卸载后使用 SHChangeNotify 通知 Shell 重读精确项目与图标关联。程序不删除 Windows 全局
图标缓存文件，不强制重启 Explorer，不篡改用户任务栏数据库。

三、网络与隐私边界
--------------------

客户端只在用户允许启动检查或主动检查时读取 api.github.com 上本项目正式 Release。只有用户确认一键更新后
才下载同一 Release 的 SHA256SUMS.txt 与精确版本 setup。程序不上传本地内容。源码中未发现其他 HTTP 服务、
Socket/WebSocket/FTP、遥测 SDK、广告 SDK 或动态载荷。

程序不读取聊天数据库、账号、Cookie、联系人、凭据、剪贴板、摄像头、麦克风或屏幕。诊断仅写本地程序目录
data/diagnostics，不自动上传。

四、进程、句柄与客户端边界
----------------------------

客户端路径必须符合微信/企业微信文件名、产品元数据和有效腾讯 Authenticode 签名。实例统计只读当前 Windows 会话中匹配
同一官方路径的进程树。程序不结束微信或企业微信；覆盖安装只处理精确安装目录中的助手进程。

句柄释放限制于已知微信/企业微信互斥锁名和精确路径 lock.ini，未扩展为任意句柄关闭。未发现 CreateRemoteThread、
WriteProcessMemory、VirtualAllocEx、DLL 注入或客户端二进制补丁。

五、注册表与崩溃恢复
----------------------

企业微信 multi_instances 修改在短期启动会话前写入 data/recovery 落盘事务；正常/异常结束后仅在当前值仍等于助手
临时状态时恢复。第三方已写入新值时保留新值，避免旧快照覆盖外部设置。其余注册表写入只有当前用户卸载登记；
未发现 Run/RunOnce、计划任务、服务或驱动持久化。

六、数据、更新与删除边界
------------------------

设置、主题、诊断、恢复、日志和更新证据位于程序目录 data。程序拒绝数据目录链接/联接。更新前要求 GitHub asset digest、
SHA256SUMS 和下载文件 SHA-256 三方一致，再验证计划、父进程、时效、目标身份和文件哈希。安装版/绿色版替换
使用同卷暂存、逐文件备份和逆序回滚，data 不进入替换清单。

完整清理对安装目录、绿色包、发布目录和可选源码分别验证专用标记、精确结构、解析后路径与链接属性；拒绝磁盘根、
系统目录、未标记目录和目录联接。

七、构建与供应链
------------------

业务程序无 NuGet 包和第三方运行 DLL。项目文件中未发现预构建/后构建 Exec、远程导入、隐藏下载或不明嵌入载荷。
版本号已收拢到 Directory.Build.props，发布脚本在构建前后校验参数、manifest 和四个二进制版本。GitHub Actions
仅 contents: read，官方 Action 固定到明确提交，并生成/验证 SPDX 2.2 SBOM。

八、发布验证与已知限制
------------------------

正式发布前执行 Release 重建、全部自动测试、14 场景 UI 回归、两次确定性组包、SHA-256 复核、全新 GitHub-hosted
Windows 重建、SPDX 2.2 SBOM 生成/验证，以及 Kaspersky 对最终 CI 工件原件扫描。未检出只是证据而非绝对保证。

项目未购买公共信任代码签名证书，Windows 或安全软件可能因“未知发布者”、低信誉或启发式模型提示。不应盲目忽略，也不应
关闭安全软件；应对照正式 Release 哈希、源码标签、CI、SBOM 和扫描日志复核。腾讯未承诺第三方多开机制长期稳定，客户端
策略改变时可能需要更新兼容层。
