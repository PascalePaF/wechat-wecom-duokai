# V1.0.9 一键更新安全验证报告

验证对象：`PascalePaF/wechat-wecom-duokai` V1.0.9  
验证范围：版本检查、品牌升级兼容、下载校验、安装版/绿色版更新事务、失败回滚与本地数据保留。

## 1. 本版风险变化

V1.0.9 的代码变化集中在产品名称、图标资源、WPF 布局、设置内软件介绍、旧快捷方式迁移、文档和 UI
回归。多开核心、客户端签名校验、网络目的地、更新协议、删除边界及企业微信注册表恢复算法没有扩大。
新增 Logo 是静态本地资源，不包含脚本、链接、网络请求或可执行载荷。

## 2. 更新来源与用户确认

- 版本元数据只读取固定仓库 `PascalePaF/wechat-wecom-duokai` 的 GitHub 正式 Release。
- 启动检查可在设置中关闭；手动检查始终由用户点击。
- 检测到新版本不会自动下载或执行。用户再次点击“一键更新”并确认后才开始。
- 浏览器打开 Release 的手动下载路径继续保留。

## 3. 三方 SHA-256 与执行限制

安装前必须同时满足：GitHub Release API 返回的附件 digest、同一 Release 中 `SHA256SUMS.txt` 的精确
文件项、实际下载文件的本机 SHA-256 三者一致。附件必须位于规范 GitHub Release 下载 URL，文件名必须
精确匹配目标版本 setup，重名、缺失、非 HTTPS、跨主机、嵌套路径、摘要缺失或大小不符均拒绝执行。

下载及更新计划只写入当前程序目录的 `data\updates`。安装器会重新核对计划路径、包身份、目标目录标记、
父进程和 SHA-256；安装版与绿色版都使用同卷暂存和逐文件备份，失败时恢复旧文件，且不覆盖 `data`。

## 4. 品牌升级兼容

面向用户的名称改为“开开助手”，但以下身份保持稳定：

- 主程序 `wechat_duokai.exe`、安装目录 `WechatDuokai`、卸载注册表键和互斥量；
- 安装/绿色目录标记、用户数据标记、更新协议及 GitHub 仓库；
- 设置键、主题、诊断、注册表恢复日志与历史迁移逻辑。

因此 V1.0.8 可原地升级。安装或更新成功后创建“开开助手”开始菜单/桌面快捷方式，再对三个精确旧路径
执行迁移；旧开始菜单目录只有在为空时才删除，不会递归删除意外文件。

## 5. 自动回归

- 当前版本 `1.0.9` 与模拟下一版本 `1.0.10` 的比较、附件名称、URL、大小和 digest 校验；
- 重名附件、非 GitHub 主机、非规范下载路径与重复校验项拒绝；
- 安装版/绿色版事务完成后文件版本为 `1.0.9`，清理器文件名与版本一致；
- 中断替换后回滚，安装版保留 `data`，绿色版保持绿色身份；
- 主界面新名称和 Logo、常规/软件介绍切换、被移走说明的可达性；
- 14 场景 UI 快照、双主题舒适度、窗口缩放、安装后显式启动策略；
- 注册表异常恢复、外部冲突保护、实例分组、本地诊断与全部运行数据目录限制。

## 6. 结论

在固定仓库、用户二次确认、三方 SHA-256、标记目录、事务替换和回滚约束内，V1.0.9 的品牌升级不会
引入新的远程执行来源或隐私上传路径。正式发布仍须由 GitHub Actions 的全新 Windows Server 2022 环境
重建，复核 SHA-256 和 SPDX SBOM，并对该 CI 原件执行 Kaspersky 扫描后再公开 Release。
