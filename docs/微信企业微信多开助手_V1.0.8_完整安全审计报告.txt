微信 · 企业微信多开助手 V1.0.8 完整安全审计报告

报告日期：2026-09-19
审计对象：PascalePaF/wechat-wecom-duokai V1.0.8 源码、构建脚本和候选发布文件

一、结论摘要

V1.0.8 的新增改动限定在夜间主题颜色、微信/企业微信图标外层主题背景、主界面页脚入口整理、设置页
诊断入口和对应自动测试。复核未发现上传聊天、联系人、账号、凭据、路径、诊断或日志的实现；未发现
远程控制、键盘记录、屏幕采集、DLL 注入、隐藏启动项、服务、驱动或修改客户端文件的代码。

本版本没有扩大网络范围：用户允许启动检查或主动点击检查时，只读取本项目 GitHub 最新正式 Release；
只有用户明确确认一键更新后，才下载同一 Release 的 SHA256SUMS.txt 和精确命名的 setup。程序不上传
本机内容。

二、夜间主题与资源安全

- 原先两个客户端图标的浅色背景是 XAML 中写死的视觉颜色，不是网络图片、动态下载或隐藏载荷；
- V1.0.8 将其改为内置主题画刷，日间仍为浅色，夜间改为深墨绿和深蓝灰；
- 图标 PNG 是随源码构建的透明背景静态资源，没有脚本、链接或可执行内容；
- 夜间成功绿、信息蓝、品牌金、警告与危险色统一降低亮度和饱和度；
- 自动测试限制关键颜色与图标背景的亮度，并验证实际控件绑定到动态主题资源；
- 主题选择只写入程序目录 `data\theme.ini`，不联网、不读取账号资料。

三、入口移动

主界面页脚移除常驻“诊断”和“发布版本”，只保留“设置”。诊断按钮移动到设置页，底层仍调用同一
DiagnosticReportService，只在 `<程序目录>\data\diagnostics` 创建本地文本报告并由用户决定是否打开
文件夹。发布入口移动到设置页“版本与更新”区域，仍只打开本仓库 GitHub Release 页面。

入口位置变化没有新增后台进程、计划任务、Run/RunOnce、管理员权限、文件删除或网络上传。

四、既有高风险面复核

- 微信/企业微信句柄逻辑只针对已知单实例锁白名单，不注入、不写内存、不结束客户端进程；
- 企业微信 `multi_instances` 仍使用修改前落盘事务、崩溃/断电恢复和外部冲突保护；
- 自定义客户端仍要求允许的文件名、产品身份和有效腾讯 Authenticode 签名；
- 所有持久运行数据仍位于程序目录带标记的 `data`，拒绝数据根目录重解析点；
- 完整清理仍依赖专用标记、结构、精确路径、重解析点拒绝和多重确认；
- 目标窗口数仍为微信与企业微信共用的单一 1–10 本地配置；
- V1.0.7 的更新信任链、同卷暂存、逐文件备份、失败回滚和 `data` 排除规则保持不变。

五、更新与供应链

一键更新只接受本项目正式 GitHub Release 中状态、版本、大小、路径和名称均符合要求的附件。GitHub
附件 digest、SHA256SUMS.txt 和下载文件三方 SHA-256 必须一致。最终哈希到启动 setup 期间保持文件
不可写；setup 再核对自身哈希、版本、计划、父进程、目标路径和目录身份。

正式 V1.0.8 必须由 GitHub Actions 的全新 Windows Server 2022 环境重建，运行完整测试，复核发布哈希，
生成并验证 SPDX 2.2 SBOM。发布前还要下载该次 CI 原始附件，用本机 Kaspersky 执行全部文件扫描并公开
原始日志。零检出是一项证据，不是绝对安全保证。

六、未签名与剩余风险

项目没有 Authenticode 商业证书。新的未签名哈希叠加进程句柄、锁文件、短时注册表和自更新行为，可能
触发未知发布者、SmartScreen、低信誉或启发式提示。用户不应关闭安全软件或设置全局白名单，应从正式
Release 下载、核对标签与 SHA256SUMS.txt；明确告警应先隔离和核查。

腾讯没有公开承诺第三方多开机制长期稳定。官方客户端改变锁或注册表策略时，本工具可能失效；当前实现
会失败关闭，不会转向注入、破解或修改客户端。GitHub 发布权限完全失守或本机用户会话已被恶意控制，
不属于三方哈希能单独解决的范围。

七、最终判断

当前源码未发现后门、隐私上传或病毒载荷。V1.0.8 的视觉与入口调整没有扩大敏感权限、网络或删除边界；
夜间图标浅色底已经改为可审计的动态主题资源，并加入回归约束。发布文件仍需以正式 CI、公开哈希、SBOM
和 Kaspersky 原始扫描日志共同核验。
