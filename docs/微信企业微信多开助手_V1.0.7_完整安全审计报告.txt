微信 · 企业微信多开助手 V1.0.7 完整安全审计报告

报告日期：2026-09-16
审计对象：PascalePaF/wechat-wecom-duokai V1.0.7 源码、构建脚本和候选发布文件

一、结论摘要

V1.0.7 新增由用户确认的一键更新。源码检查未发现上传聊天、联系人、账号、凭据、文件、诊断或日志的
实现；未发现远程控制、键盘记录、屏幕采集、DLL 注入、隐藏启动项或修改微信/企业微信程序文件的代码。

本版本的网络范围不再只是 Release 版本号：

1. 用户开启启动检查或主动点击检查时，读取本项目 GitHub 最新正式 Release 元数据；
2. 只有用户在确认框点击“是”后，才下载同一 Release 的 SHA256SUMS.txt 和正式 setup 附件；
3. 不向 GitHub 或其他服务上传本地内容。

二、更新信任链

- 仓库固定为 PascalePaF/wechat-wecom-duokai；
- 初始附件 URL 必须是 HTTPS、github.com、本仓库 Release、目标标签和精确文件名；
- 附件状态必须为 uploaded，大小必须处于固定上限内；
- GitHub API digest、SHA256SUMS.txt 记录和下载文件 SHA-256 三方一致；
- SHA256SUMS.txt 自身也用 GitHub digest 校验；
- setup 从最终哈希计算到启动期间保持不可写；
- 安装程序再次核对自身哈希、版本、更新计划、父进程、目标路径和目录身份。

任何缺失、重复、重定向前 URL 异常、大小变化、哈希冲突或路径身份异常都会停止更新，不会降级成“继续
执行”或“忽略校验”。

三、覆盖与回滚

更新只接受带项目专用标记的安装版或绿色版目录。两个身份标记同时出现时拒绝。程序文件先释放到
data\updates 下的同卷暂存目录；每替换一个旧文件都保留备份。任一步骤失败时按相反顺序恢复。

data 本身不在替换白名单，所以以下内容保留：

- settings.ini 和 theme.ini；
- 自定义微信/企业微信路径；
- diagnostics；
- recovery 和注册表恢复日志；
- updates 与 update.log。

四、安装版与绿色版边界

安装版更新后只刷新本产品的开始菜单快捷方式、已有桌面快捷方式和 HKCU 卸载登记。绿色版不会写入卸载
登记或创建快捷方式；它只原地替换程序文件与随包说明，并清理旧版本命名的清理器副本。

五、持久文件

新增文件仍全部位于程序目录：

- data\updates：校验文件、下载包、短期计划、事务暂存和备份；
- data\logs\update.log：更新版本、模式、结果和失败类型。

日志不记录哈希以外的下载内容、账号、客户端路径或用户资料，不会自动上传。更新下载包会在后续启动中
按受限文件名和时间清理；正在运行或过新的文件不会被强制删除。

目标窗口数在 V1.0.7 恢复为两个客户端共用的单一配置。V1.0.6 的旧微信值优先，企业微信值仅在前者
缺失时作为备选；合并后删除两个旧键。该迁移只处理本地数字设置，不新增网络或权限边界。

六、原有高风险面复核

- 微信/企业微信进程句柄逻辑仍只用于已知单实例锁；
- 企业微信 multi_instances 仍使用断电恢复事务和第三方冲突保护；
- 客户端自定义路径仍要求文件名、产品身份和腾讯数字签名；
- 完整清理仍依赖专用目录标记，不以普通路径猜测删除范围；
- 未增加管理员权限请求、服务、驱动、计划任务、Run/RunOnce 或后台常驻更新进程。

七、构建与发布门禁

正式 V1.0.7 必须由 GitHub Actions 的全新 Windows Server 2022 环境构建，执行全部自动化测试，生成并
复核 SHA-256，生成和验证 SPDX 2.2 SBOM。发布前还要下载该次 CI 原始产物，由本机卡巴斯基扫描；原始
日志与病毒库日期作为 Release 附件提供。扫描未检出不能被描述为绝对安全保证。

八、未签名与剩余风险

项目没有 Authenticode 商业证书。setup 会下载后执行，且程序具有进程句柄与企业微信临时注册表行为，
因此启发式产品可能给出信誉或行为提示。用户不应关闭安全软件或设置全局白名单，应从正式 Release 下载、
核对 SHA256SUMS.txt，并确认提示中的路径和版本。

GitHub 仓库发布权限完全失守或本机当前用户会话已经被恶意控制，不属于三方哈希能够单独解决的范围。
如项目未来面向更大规模用户，应继续评估受保护的代码签名和发布证明。

九、最终判断

当前源码未发现后门、隐私上传或病毒载荷。V1.0.7 的一键更新采用明确确认、固定来源、三方哈希、启动前
不可写窗口、安装程序二次验证、标记目录限制和事务回滚；在未使用付费代码签名的前提下，已经建立了可
审计、失败关闭且兼容安装版/绿色版的更新链路。
