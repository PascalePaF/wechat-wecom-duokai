# V1.1.0 一键更新安全验证报告

验证对象：`PascalePaF/wechat-wecom-duokai` V1.1.0  
验证范围：版本身份、V1.0.11 → V1.1.0 更新兼容、安装版/绿色版事务、哈希、数据保留与回滚。

## 结论

V1.1.0 不更改安装目录身份、主 EXE 名称、数据标记、卸载登记键、AppUserModelID 或更新协议。
V1.0.11 安装版与绿色版均可在原目录更新；`data` 目录不进入替换列表。新增客户端退出按钮不参与
安装器的运行中助手检测，也不会让安装或更新流程自动结束微信/企业微信。

## 版本与附件

- `Directory.Build.props` 中唯一产品版本为 `1.1.0`。
- 三个 Windows manifest 与 app/core/setup/cleanup 文件版本必须为 `1.1.0.0`。
- 正式附件名固定为 `wechat_duokai-setup-v1.1.0.exe`、`wechat_duokai-cleanup-v1.1.0.exe` 和
  `wechat_duokai-portable-v1.1.0.zip`。
- 标题、版本徽标、安装器、清理器、HTTP User-Agent、构建脚本与 CI 均从同一版本源或发布参数校验。

## 更新信任链

1. 只读取 `PascalePaF/wechat-wecom-duokai` 的最新非草稿、非预发布 GitHub Release。
2. Release 附件必须使用精确规范名称、同仓库下载 URL、非零合理大小、无重名，并携带可解析 SHA-256 digest。
3. 用户点击“一键更新”并再次确认后，才下载 `SHA256SUMS.txt` 与精确版本 setup。
4. GitHub digest、校验文件记录和本机下载文件 SHA-256 三者必须完全一致。
5. 最终校验至启动安装器期间保持包文件不可写；独立安装器再次验证计划时效、父进程、目标目录、版本和哈希。
6. 安装版与绿色版使用同卷暂存、逐文件备份和逆序回滚；更新失败时恢复上一版本，保留 `data`。

## V1.1.0 退出功能与更新隔离

- “全部退出”只存在于主程序客户端卡片中，必须由用户明确点击和确认。
- 安装器覆盖更新仍只询问并处理目标安装目录中的“微窗助手”自身进程。
- 一键更新不会调用微信/企业微信退出功能，也不会把客户端 PID 写入更新计划。
- 客户端关闭逻辑位于可测试的进程环境抽象中，不扩大发布附件来源、下载目录或安装器权限。

## 发布门禁

- Release x64 全量重建和完整自动测试；
- 14 场景日间/夜间 UI 渲染与人工视觉检查；
- 本地重复组包关键文件 SHA-256 一致；
- GitHub-hosted `windows-2022` 环境重建、哈希复核、SPDX 2.2 SBOM 生成与验证；
- Kaspersky 对最终 CI 工件原件扫描，完整日志随 Release 发布；
- `v1.1.0` 标签只指向通过门禁的源码提交。
