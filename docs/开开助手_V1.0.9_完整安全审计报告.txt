开开助手 V1.0.9 完整安全审计报告
==================================

审计日期：2026-09-19
审计对象：PascalePaF/wechat-wecom-duokai V1.0.9 源码、构建脚本和候选发布文件
审计重点：新 Logo、产品更名、主界面精简、软件介绍页、快捷方式迁移及既有安全边界

一、结论摘要
------------

未发现后门、隐私数据上传、聊天数据读取、键盘记录、远程控制、挖矿、下载任意载荷、DLL 注入、远程线程、
客户端文件篡改或绕过腾讯数字签名验证的代码。V1.0.9 的新增资源为本地静态 SVG/PNG/ICO；新增界面逻辑
只在同一 WPF 窗口中切换常规设置和软件介绍，不增加网络、注册表或文件系统权限。

“未发现”是对当前源码和构建产物的审计结论，不是绝对安全保证。正式文件仍需通过干净 Windows CI 重建、
SHA-256、SPDX SBOM 和 Kaspersky 原始扫描日志共同核验。本项目没有受公共信任的代码签名证书，首次运行
可能出现未知发布者或启发式信誉提示；不得把“未签名”简单等同于病毒，也不得盲目忽略明确告警。

二、V1.0.9 新增内容审计
----------------------

1. 品牌资源
   - KaikaiLogo.svg 是可读的本地矢量路径，只包含两个圆角窗口和一个识别点。
   - KaikaiLogo.png 是透明静态位图；favicon.ico 仅封装 16、20、24、32、40、48、64、128、256 像素 PNG 帧。
   - 资源不包含宏、脚本、URL、元数据执行入口或网络行为。

2. 产品名称
   - 面向用户统一为“开开助手”。
   - 主 EXE、数据目录标记、安装目录、卸载注册表键、互斥量和更新仓库保持不变，以兼容旧版原地升级。
   - 文件属性、窗口、安装器、清理器、开始菜单和桌面快捷方式显示新名称。

3. 快捷方式迁移
   - 安装/更新先创建新快捷方式，再删除两个精确旧名称链接。
   - 旧开始菜单目录只有在精确旧链接删除后且目录为空时才删除。
   - 如果旧目录含有未知文件则保留目录，不执行递归清理。
   - 完整卸载仍以精确路径、目录标记和计划文件校验为前提。

4. 界面与说明
   - 主界面删除低频说明，仅保留应用、目标数量、实时窗口数和设置入口。
   - 被移除说明移入“设置 → 软件介绍”，没有隐藏功能或改变实际行为。
   - 设置页切换只修改 WPF Visibility、字重和透明度，不访问外部资源。

三、隐私与网络
--------------

- 不读取聊天数据库、联系人、消息、文件、Cookie、登录令牌、账号或密码。
- 不上传诊断、配置、客户端路径、窗口数量、注册表状态或日志。
- 用户启用启动检查或手动检查时，只向 api.github.com 请求本项目最新正式 Release 元数据。
- 只有用户确认一键更新后才下载同一 Release 的 SHA256SUMS.txt 和精确 setup 附件。
- 普通 HTTPS 请求会向 GitHub 暴露网络通信必需的 IP、TLS 信息和 User-Agent；除此之外没有遥测。

四、多开与企业微信注册表边界
----------------------------

- 微信和企业微信实例按当前 Windows 会话、经验证的程序路径和根进程关系统计。
- 只启动“目标数减当前根实例数”的缺口；不会为了补开而结束现有客户端。
- 只释放白名单中的已知单实例锁，不扫描或关闭任意句柄。
- 企业微信临时注册表状态写入前先把恢复事务强制落盘到 data\recovery。
- 正常退出或下次启动恢复时，只有当前值仍等于助手临时值才写回旧快照；第三方新值会保留。
- 恢复、冲突和失败证据写入 data\logs，不自动上传。

五、本地文件、安装、更新与删除边界
----------------------------------

- 所有持久运行文件位于程序目录 data 子目录；不向 AppData 新增运行配置。
- 手动选择的微信/企业微信必须通过允许的文件名、产品信息和腾讯 Authenticode 签名校验。
- 覆盖安装只识别目标安装目录中精确路径的开开助手进程，不结束微信、企业微信或其他目录程序。
- 安装完成后必须由用户点击“确认并启动”。
- 一键更新限制为固定 GitHub 仓库、规范附件 URL、精确版本文件名和三方 SHA-256 一致。
- 更新使用同卷暂存、逐文件备份和失败回滚，不覆盖 data。
- 删除安装、绿色版、发布包或源码前，必须通过专用标记、精确路径、结构和非链接校验。

六、发布前强制验证
------------------

1. Release 配置完整重建并运行全部自动测试。
2. 自动生成 14 场景 UI 回归截图并人工检查新 Logo、精简主界面和软件介绍双主题。
3. 连续两次本机构建对 SHA256SUMS.txt 中的五个核心文件执行确定性对比。
4. GitHub Actions Windows Server 2022 全新环境重建、测试、哈希复核并生成/验证 SPDX 2.2 SBOM。
5. 下载 main 工作流的精确 CI 原件，对整个目录运行本机 Kaspersky 扫描并保存原始日志。
6. 只有以上步骤完成后，才在同一源码提交创建 V1.0.9 标签并公开 GitHub Release。

七、最终判断
------------

当前源码未发现病毒或后台上传隐私数据的链条。V1.0.9 的品牌和界面调整没有扩大敏感权限、网络目的地、
注册表范围或删除范围。用户应仅从官方 GitHub Release 下载，核对 SHA-256，保持安全软件开启；若收到明确
检测名称和对象的告警，应先隔离并比对源码、哈希、SBOM 与扫描日志，而不是直接点击忽略。
