# V1.1.1 全项目自查报告

审查对象：`PascalePaF/wechat-wecom-duokai` V1.1.1  
审查日期：2026-09-20（Asia/Tokyo）  
范围：更新检查、下载校验、主程序、多开/退出、注册表恢复、安装/清理、构建链、测试与发布资料。

## 1. 结论

V1.1.1 的现场故障来自 GitHub 未登录 REST API 每小时 60 次配额耗尽，而不是恶意代码、后台上传、
反病毒拦截或仓库失效。旧版每次检查都直接访问 `api.github.com`，收到 HTTP 403 后又隐藏了错误详情。

本版将“发现最新版”和“取得可选附件 digest”拆开：版本号使用不受 REST API 配额限制的 GitHub
Release 跳转；只有存在新版本时才尝试 API。API 不可用不会再阻断检查，而是进入边界更明确的固定
Release 清单校验模式。全仓库复查未发现后台上传隐私、读取聊天或账号、代码注入、隐藏持久化、远程
控制、客户端文件修改、任意进程终止或无标记任意目录删除代码。

## 2. 更新检查边界

| 阶段 | 行为 | 保护 |
| --- | --- | --- |
| 版本发现 | HEAD 固定的本项目 `releases/latest` | 只接受 HTTPS、github.com、精确 tag 路径、无查询/片段 |
| 版本比较 | 本地解析 `v<数字版本>` | 无法解析时失败关闭；相同版本不访问 API |
| 摘要增强 | 只在有新版本时尝试固定 API | 403、超时、连接失败均可安全降级 |
| 附件确认 | HEAD 精确 tag/setup/清单地址 | 最终交付域属于 GitHub，大小必须在上限内 |
| 用户确认 | 显示版本、大小和当前校验模式 | 未确认不下载文件正文 |
| 下载校验 | 清单唯一记录与 setup SHA-256 一致 | API 可用时额外要求两个 GitHub digest 一致 |
| 执行更新 | 启动前锁定并复算；交给独立安装器 | 标记目录、计划时效、暂存、备份和回滚不变 |

## 3. 安全与隐私复查

### 网络

- 代码中的网络目标只包括本项目 `github.com` Release、`api.github.com` 元数据及 GitHub 官方附件交付域。
- 未发现上传请求、遥测、广告、Socket、WebSocket、FTP、任意远端 URL 配置或动态代码执行。
- 请求只携带普通 User-Agent；不上传诊断、路径、账号、日志或设备标识。

### 多开、退出与注册表

- 微信/企微启动仍只处理已经验证的腾讯签名程序与白名单单实例锁；不注入 DLL、不写客户端内存。
- V1.1.0 的分端全部退出仍必须用户点击并确认，只处理当前 Windows 会话和实时精确路径匹配的进程。
- 企业微信 `multi_instances` 仍使用修改前落盘事务、异常启动恢复和外部冲突保护；本版未扩大注册表范围。

### 文件、安装与清理

- 配置、主题、诊断、恢复、日志和更新文件仍在程序目录 `data` 下。
- 更新只覆盖带安装版/绿色版专用标记的目录，永不把源码目录当作自动更新目标。
- 清理器继续检查专用标记、目录结构、精确路径和重解析点；本版未扩大递归删除目标。

### 构建供应链

- 业务项目无新增 NuGet 运行包、第三方 UI DLL、自定义远程构建脚本或二进制载荷提交。
- GitHub Actions 使用只读权限、固定提交的官方 Action、全新 Windows Server 2022，重建、测试、复核哈希
  并生成/验证 SPDX 2.2 SBOM。
- 项目仍无 Authenticode 代码签名；应核对正式 Release、SHA-256、CI、SBOM 和 Kaspersky 扫描日志。

## 4. 自动与现场验证

- 完整既有 smoke tests 通过。
- 新增 API 403 / `X-RateLimit-Remaining: 0` 回归通过。
- 非 GitHub最新版本地址、恶意附件 URL、嵌套路径、重复附件、无效 digest 继续拒绝。
- HttpClient 超时与用户取消分支分离；超时显示具体提示，不会永久停在“正在检查”。
- 本机真实配额为 0 时，修复版仍发现 V1.1.0，取得 setup 761,856 字节、清单 580 字节并允许一键更新。
- 数量迁移、增量补开、企业微信恢复、退出边界、更新回滚、安装/清理、Shell 图标、响应式布局与锁释放
  自动测试继续通过。

## 5. 剩余限制

- API 降级模式没有 GitHub 服务端独立 digest，以固定 HTTPS 来源、严格路径/域名/大小和
  `SHA256SUMS.txt`/下载文件一致替代；没有代码签名时无法建立仓库之外的独立发布信任根。
- GitHub 或本机网络完全不可达时只能显示具体原因并提供浏览器发布页入口。
- 腾讯没有公开承诺第三方多开机制长期稳定；客户端变更后工具会失败关闭，不会转向注入或破解。
- 反病毒未检出不是绝对安全证明；首次使用仍建议测试账号，并保持安全软件开启。
