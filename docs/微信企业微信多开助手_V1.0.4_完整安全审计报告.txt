微信 · 企业微信多开助手 V1.0.4 完整安全审计报告

文档编号：WD-SA-2026-09-14-V104
报告日期：2026-09-14（Asia/Tokyo）
审计对象：PascalePaF/wechat-wecom-duokai V1.0.4 源码、构建逻辑和候选发布文件

一、执行结论

截至候选源码复核，没有发现读取聊天内容、窃取账号或凭据、隐私上传、远程控制、隐藏下载、
客户端代码注入、开机自启或后台常驻服务的实现。程序不会修改、替换或破解微信/企业微信文件。

V1.0.4 新增的企业微信三开兼容模式会枚举同一 Windows 会话中、可执行路径精确匹配已验证腾讯
客户端的进程句柄，只关闭名称匹配 Tencent.WeWork.ExclusiveObject* 的互斥锁。它不会关闭视频
对象，不会写客户端内存，不会创建远程线程，也不会结束已经运行的企业微信进程。

企业微信注册表操作已从“永久写目标数量”改为短期启动会话：先保存 multi_instances 是否存在、
原始值及 RegistryValueKind；双开期间临时使用 DWORD 2；三开及以上期间临时删除这条只支持双开
的提示；启动循环在 using/finally 退出时恢复原状态。注册表被第三方并发锁定或权限突然改变时只能
尽力恢复，这是剩余的低风险边界，不能宣传为绝对保证。

本结论不是“绝对安全保证”。跨进程句柄枚举与白名单句柄关闭属于底层兼容操作，容易被安全软件的
启发式模型关注，也是 Windows 或腾讯客户端更新后的主要兼容风险。正式使用应核对 GitHub Release、
源码标签、SHA-256 和本机安全软件结果。若出现明确告警，应先隔离调查，不能要求用户盲目忽略、
关闭防护或设置永久白名单。

二、V1.0.4 新增能力及控制

1. 企业微信三开及以上
   - 真机对象：官方 WXWork.exe 5.0.11.6018，腾讯 Authenticode 状态 Valid；
   - A 组：multi_instances=3 最终只有 2 个根实例，证明该入口不是任意数量开关；
   - B 组：不使用注册表双开提示，逐次精确释放独占互斥锁，成功从 0 启动至 3 个根实例；
   - 测试结束通过窗口正常退出三个测试实例，最终 WXWork 进程为 0；
   - 测试前该注册表值不存在，测试后继续不存在；
   - 正式代码仍限制目标为 1–10，但只声明当前版本已验证三个，不保证所有版本四至十开。

2. 注册表短期策略
   - IWeComLaunchPolicy 将注册表准备与 InstanceManager 分离，可注入测试替身；
   - 当前用户命名信号量防止多个助手同时交错保存/恢复同一值；等待放在后台，异步续体换线程也可安全释放；
   - 目标 1 不修改；目标 2 临时设 2；目标 3–10 临时删除；
   - 恢复同时保留原值类型，原来不存在时不留下新值；
   - 准备失败时不崩溃、不提权，回退为精确锁尝试；
   - 恢复异常被限制在该当前用户值，不扩大写入范围。

3. 比例界面
   - 901×513 是明确最低尺寸，删除包裹工作区的 ScrollViewer；
   - 窗口只允许放大，不把界面缩到不可读；
   - 使用相同 ScaleX/ScaleY，避免文字和图标非等比变形；
   - 逻辑画布尺寸按缩放因子反算，变换后覆盖全部视口；
   - 左右卡片按 2.4:1 分配额外宽度，超宽屏不留巨量空白；
   - 保留 WPF、动态双主题和 Per-Monitor V2 DPI，没有增加 WebView、脚本运行时或第三方 UI 包。

4. 代码签名决定
   - 按项目决定，本版不购买证书、不申请托管签名，也不使用会误导普通用户的自签证书；
   - release-manifest 明确 Signed=False；
   - 未签名不是恶意证据，也不是安全证明；
   - 用公开源码、Git 标签、构建脚本、SHA-256、自动测试和反病毒原始日志提供可核验链。

三、继承的安全边界

- 主程序、安装器、清理器均为 asInvoker、uiAccess=false；
- 不安装驱动、服务、计划任务、浏览器扩展或开机启动项；
- 不请求或启用 SeDebugPrivilege；
- 不使用 WriteProcessMemory、CreateRemoteThread、VirtualAllocEx、SetWindowsHookEx 或 DLL 注入；
- 不读取聊天数据库、消息、联系人、账号、Cookie、登录凭据、浏览器资料或剪贴板；
- 用户配置只含目标数量与官方客户端路径，位于 %LOCALAPPDATA%\WechatDuokai；
- 诊断只在用户点击后写入程序目录 diagnostics，不自动上传；
- 唯一自动网络请求是固定 api.github.com Release 元数据 GET，只解析 tag_name；
- 没有安装包下载、自动替换、自执行更新、遥测 SDK、广告 SDK或自定义服务器；
- 自定义客户端必须同时通过文件名、产品信息、WinVerifyTrust 和 Tencent 签名主体检查；
- 进程路径读不到时失败关闭，不按进程名猜测；
- 覆盖安装只处理所选安装目录中的本助手，不关闭微信、企业微信或其他目录程序；
- 清理器继续使用专用标记、精确目录、重解析点拒绝、结构校验和多重确认。

五、句柄操作核查

WindowsHandleUnlocker 获取的进程权限仅为 PROCESS_DUP_HANDLE。句柄列表来自系统快照；每个候选
句柄先复制到本进程读取类型和名称，只有满足白名单才以 DUPLICATE_CLOSE_SOURCE 关闭源句柄。

企业微信白名单：Tencent.WeWork.ExclusiveObject 子串。
微信白名单：已知 WeChat/Weixin Instance Identity Mutex 名称；现代微信另外只允许精确的
%APPDATA%\Tencent\xwechat\lock\lock.ini 文件路径。rundll32 只可参与这一精确 lock.ini 文件匹配，
不能参与任意互斥锁匹配。

没有模糊匹配“Exclusive”全部对象，没有关闭未知产品锁，没有全系统终止进程。未来客户端锁名变化时，
正确行为是失败并记录诊断，而不是扩大通配范围。

八、未签名与启发式告警解释

V1.0.4 没有受公共信任的 Authenticode 签名。新生成、低下载量且会跨进程枚举/关闭特定句柄的程序，
可能被信誉、启发式或云监测系统拦截。启发式/云监测表示安全产品依据行为特征和云端信誉作判断，
不等于已经证明存在某个病毒家族；但也绝不能据此直接忽略。

遇到告警应：保留隔离；记录产品名、病毒库时间、检测名称、文件 SHA-256；与 Release 的 SHA256SUMS
比对；确认下载域名和标签；查看本报告及源码；必要时向安全厂商提交误报复核。只有证据一致且复核
可接受时才由用户自行决定恢复，不应关闭实时保护。

九、剩余风险

1. NtQuerySystemInformation/NtQueryObject 属于底层接口，Windows 更新可能改变结构或可用性；
2. 腾讯没有公开保证第三方多开机制，未来微信/企微可更换锁、进程架构或增加策略；
3. 企业微信只实测 5.0.11.6018 的三个根实例，不能外推为所有版本十开；
4. 多开可能受到组织管理、许可条款、账号风控和设备策略限制；
5. 命名信号量只能协调使用本策略的助手实例，第三方程序并发改写注册表时恢复只能尽力而为；
6. 自动版本检查引入 GitHub 可用性和普通请求元数据边界；
7. 安装目录由当前用户写入，同一账户已完全失陷时，目录标记不是密码学防线；
8. 删除源码是不可逆操作，执行前必须推送或备份未提交内容；
9. 未签名新构建仍可能被安全产品告警，本机零检出不能替代厂商实验室判定；
10. 第三方客户端或非官方修改版不在验证范围，手动选择也会因签名/产品身份不符而拒绝。
