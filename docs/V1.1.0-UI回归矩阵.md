## 自动断言

- 微信和企业微信卡片必须各自暴露一个“全部退出”按钮，运行数量为 0 时不可用。
- 页脚两行必须保持左对齐；微信/企微数字分别使用绿/蓝动态资源、粗体和至少 8 像素左右留白。
- 屏幕阅读器动态名称必须保留完整句子，而不是只读出孤立数字。
- 左上标题区不再包含独立的“微信 · 企业微信”副标题。
- “应用”和“目标窗口数”卡片必须同一顶部、同一高度，并使用相同四行比例轨道。
- 最小尺寸下客户端路径允许省略，但图标、标题、状态、选择入口、退出和启动按钮都不可重叠或裁切。
- 主窗口扩大时文字、图标、按钮、间距、圆角和阴影使用同一非缩小比例填满窗口。
- 夜间退出按钮使用压暗危险色背景，绿色/蓝色数量和客户端图标底色继续满足舒适亮度限制。
- 设置、软件介绍、诊断、Release、检查更新与一键更新入口保持完整。
- 三个 WPF 窗口保持原生标题栏和显式绿蓝任务栏图标；快捷方式 Shell 身份测试继续通过。

## 人工检查结果

- 901×513 日间/夜间：左右外框顶部与底部一致；新增按钮与“…”、主按钮间距自然，路径文字按需截断。
- 数量卡片标题与左侧“应用”标题进入同一上方轨道；计数器和状态条垂直分布平衡。
- 退出按钮在有微信实例时清晰可见；无企业微信实例时显示低对比禁用态，不抢主操作视觉权重。
- 页脚绿色/蓝色数字比说明文字更醒目，两行总宽度稳定，右下“设置”仍处于最右侧。
- 1280×720、1920×1080 与 3440×1392：统一比例缩放，无外层滚动条、局部固定大小或大块留白。
