微窗助手 V1.1.3 完整安全审计报告
=================================

文档编号：WD-V113-SECURITY-20260920
审计日期：2026-09-20
项目地址：https://github.com/PascalePaF/wechat-wecom-duokai

一、结论
--------

V1.1.3 是 V1.1.2 静态更新架构的代理兼容修复。未发现后门、隐蔽上传、聊天/账号/凭据采集、远程控制、
广告遥测、静默执行、DLL 注入或隐藏载荷。新增逻辑只读取本机进程环境中的 HTTPS_PROXY/HTTP_PROXY，
交给 .NET Framework WebProxy 传输固定 GitHub 请求；代理地址和凭据不保存、不记录、不上传。

二、问题与修复
------------

V1.1.2 发布后的真实 .NET Framework 4.8 测试发现：浏览器和 curl 能使用环境变量代理，但旧框架默认
HttpClient 在系统代理关闭时不一定采用该环境代理，导致静态清单连接失败。

V1.1.3：
1. 优先读取 HTTPS_PROXY，缺失时读取 HTTP_PROXY；非法值忽略并保留系统默认行为。
2. 只接受 http/https、主机、端口和根路径；拒绝 file URI、额外路径、query 与 fragment。
3. 代理 user-info 可作为代理凭据，但不会进入日志、诊断、设置或 GitHub User-Agent。
4. 强制 TLS 1.2，不向旧 SSL/TLS 降级。
5. 最新静态清单的首步重定向改用 HEAD，随后才下载受 64 KiB 上限保护的 JSON。
6. setup/SHA256SUMS 下载复用同一代理策略，最终地址仍须为 GitHub 官方交付域。

三、更新安全链
------------

静态清单仍必须匹配固定仓库、版本标签、发布页、附件名称、规范 URL、大小和 SHA-256；用户确认后先核对
SHA256SUMS 文件摘要，再核对唯一 setup 条目和实际下载文件。API 可用时还要求 GitHub 服务端 digest 与
静态清单一致。文件锁、启动前复算、标记目录、更新计划时效、父进程验证、同卷暂存、备份和失败回滚
全部保持。代理兼容不放宽任何执行条件。

四、端到端证据
------------

在 HTTPS_PROXY=http://127.0.0.1:7897、系统代理关闭的现场，正式 .NET Framework 4.8 进程成功：
- 发现 V1.1.2；
- 同时取得静态清单摘要与 GitHub digest；
- 下载 SHA256SUMS.txt；
- 下载 789,504 字节 setup；
- 复算 SHA-256 ea15c122be493c5583a3a73011825c691f87e96802602128014ad4dc8a991d89；
- 多重校验通过，未执行安装包。

五、其他敏感能力复核
----------------

- 微信/企业微信定位、腾讯签名验证、根实例统计和精确锁处理未改。
- 企业微信 multi_instances 落盘事务、断电恢复和外部冲突保护未改。
- “全部退出”仍需确认，只处理当前会话和已验证精确路径。
- 诊断仍只写 data\diagnostics，不自动上传。
- 所有设置、更新状态、下载与恢复证据仍位于安装目录 data。

六、剩余限制
------------

未商业签名和低文件信誉可能触发启发式告警。环境代理由用户或启动环境控制；专有认证代理仍可能不兼容。
失败时程序不会关闭 TLS 校验或跳过 SHA-256，只会提示失败并允许打开浏览器手动下载。V1.1.2 已启用
不可变 Release，不能用同一标签替换，因此此修复使用新版本 V1.1.3 完整发布。

最终判断：V1.1.3 未扩大隐私数据面或执行面；它修复环境代理可达性，同时保持 V1.1.2 的静态清单、
多重摘要、用户确认、事务回滚和不可变发布边界。
