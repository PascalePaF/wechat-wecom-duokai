# V1.0.11 一键更新与 Shell 身份验证报告

验证对象：`PascalePaF/wechat-wecom-duokai` V1.0.11  
验证范围：版本身份、图标资源、任务栏身份、覆盖安装、快捷方式、一键更新、绿色版事务与回滚。

## 结论

V1.0.11 不改变安装目录、EXE 内部名称、数据标记、卸载登记键或更新协议。V1.0.10 安装版和
绿色版均可在原目录更新，`data` 不参与替换。新增 Shell 身份和图标刷新通知不扩大更新来源、
删除范围、注册表范围或进程控制范围。

## 图标与任务栏验证

1. `favicon.ico` 仍包含 16/20/24/32/40/48/64/128/256 像素帧。
2. 主程序、setup 与 cleanup 都使用该 ICO 作为 PE 应用图标，同时将它作为 WPF Resource。
3. 三个窗口在 XAML 中显式绑定 `Resources/AppIcon.ico`。
4. 进程启动时设置稳定 AppUserModelID；主程序、setup 和 cleanup 使用不同后缀，不会被任务栏错误合并。
5. 桌面、开始菜单主程序与卸载快捷方式通过 `IPropertyStore` 写入与目标进程相同的 `System.AppUserModel.ID`。
6. 安装/更新在写完 EXE 和 `.lnk` 后调用 `SHChangeNotify`，先通知精确项目变更，再让 Explorer 丢弃旧关联图标缓存。
7. 清理器删除自有快捷方式后发送同样通知；不直接删除 Windows 缓存数据库，不强制结束 Explorer。

## 版本一致性

- `Directory.Build.props` 是产品版本唯一代码来源，当前值为 `1.0.11`。
- WPF 标题和版本徽标从主程序程序集读取；安装引擎与更新 User-Agent 从自身程序集读取。
- `build-release.ps1` 会在编译前比对构建参数、中央版本与三个 Windows manifest，编译后再比对
  app/core/setup/cleanup 四个文件版本。

## 更新信任链

1. 只从固定仓库的正式 GitHub Release 读取元数据。
2. 模拟当前版本与下一补丁版本的比较；附件名、规范 URL、大小、重名与 digest 均有自动负向测试。
3. 下载 `SHA256SUMS.txt` 与精确版本 setup 后，GitHub digest、校验文件和本机文件三方 SHA-256 必须一致。
4. 最终校验至启动安装器期间保持文件不可写；安装器再次验证计划时效、父进程、目标目录和文件哈希。
5. 安装版与绿色版使用同卷暂存、逐文件备份和逆序回滚；中断替换时保留旧版和用户设置。

- Kaspersky 对最终 CI 工件原件扫描，原始日志随 Release 公开；
- 正式 `v1.0.11` 标签指向通过上述门禁的源码提交。
