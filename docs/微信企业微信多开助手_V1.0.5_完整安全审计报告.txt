微信 · 企业微信多开助手 V1.0.5 完整安全审计报告

文档编号：WD-SA-2026-09-16-V105
报告版本：1.0
审计日期：2026-09-16（Asia/Tokyo）
审计对象：PascalePaF/wechat-wecom-duokai V1.0.5 源码、构建逻辑和候选发布文件

一、执行结论

本次源码复核没有发现后台上传隐私数据、读取聊天记录、窃取账号或凭据、远程控制、隐藏持久化、
静默下载并执行、DLL 注入、远程线程、写客户端内存或篡改微信/企业微信程序文件的实现。

V1.0.5 新增的联网能力仍局限于版本检查：在用户允许“启动时自动检查”或主动点击“立即检查”时，
向 api.github.com 读取 PascalePaF/wechat-wecom-duokai 最新 Release 的 tag_name。客户端不会自动下载、
安装或执行 Release 附件；点击发布入口只会用系统浏览器打开 GitHub Releases。诊断报告不会上传。

企业微信扩展模式属于兼容操作而不是官方接口：只针对当前 Windows 会话、路径精确匹配且通过腾讯签名
验证的 WXWork.exe，处理已知 Tencent.WeWork.ExclusiveObject* 独占锁；不结束企业微信进程，不注入
代码，不改客户端文件。multi_instances 只在启动会话中临时使用，恢复前会比较当前状态。第三方程序
写入的新值、类型或存在状态与助手临时状态不一致时，助手会跳过恢复并保留第三方的新设置。

当前项目没有受公共信任的 Authenticode 签名。新生成、下载量低并涉及跨进程句柄枚举的工具可能触发
信誉或启发式告警。告警不应被盲目忽略；用户应核对 GitHub 来源、源码标签、SHA-256、SBOM 和本报告，
并保持本机安全软件开启。反病毒未检出也不是数学意义上的绝对安全保证。

二、V1.0.5 新增代码边界

1. 实时计数
   - 每 2 秒按精确客户端路径、当前会话和根进程关系计数。
   - 不读取窗口标题、聊天内容、账号名或消息数据库。
   - 枚举异常被局部处理，界面显示 0，不扩大权限。

2. 设置与主题
   - 自动检查开关保存在 %LOCALAPPDATA%\WechatDuokai\settings.ini。
   - 主题偏好保存在同一受标记用户数据目录的 theme.ini。
   - 设置仅包含布尔值、主题名称、目标数量和经验证客户端路径；没有凭据字段。
   - 自定义路径使用 Base64 只是配置编码，不是加密，文档已明确说明。

3. 更新检查
   - 固定 HTTPS 主机：api.github.com。
   - 固定仓库：PascalePaF/wechat-wecom-duokai。
   - 只解析 tag_name，并使用 Version 比较。
   - HTTP 超时 8 秒；取消随主窗口生命周期传播。
   - 不解析、下载、保存或执行 Release 附件。

4. 注册表恢复冲突保护
   - 原始状态保存：是否存在、值、RegistryValueKind。
   - 临时状态保存：DWORD 2 或值不存在。
   - 恢复前重新读取；只有当前状态与临时状态完全相等才恢复原值。
   - byte[] 和 string[] 使用内容比较，不依赖对象引用。
   - 第三方变更被检测时直接跳过恢复，不用旧快照覆盖。
   - 本助手实例间继续使用 Local\WechatDuokai.WeComRegistryPolicy 信号量协调。
   - 注册表普通值不支持真正跨进程原子 compare-and-swap，读取与写回之间仍有极短理论竞态窗口；报告
     没有把该保护夸大为事务。

5. GitHub Actions
   - 每次任务使用 GitHub 托管的全新 windows-2022 虚拟机。
   - checkout、setup-dotnet、setup-msbuild、upload-artifact 均固定到明确提交哈希。
   - 从源码执行 Release 重建和完整测试，不复用开发机 bin/obj。
   - SHA256SUMS.txt 生成后逐项重新计算验证。
   - Microsoft.Sbom.DotNetTool 固定为 4.1.2，生成并验证 SPDX 2.2 SBOM。
   - 工作流权限为 contents: read，不配置仓库写权限或外部发布密钥。

三、危险能力与约束复核

跨进程句柄：
- 只枚举当前会话、可执行路径精确匹配目标客户端的进程。
- 微信命名互斥锁、微信 4.x 精确 lock.ini 和企业微信已知独占锁采用白名单。
- 不终止微信或企业微信进程。

客户端选择：
- 微信只接受 Weixin.exe/WeChat.exe，企业微信只接受 WXWork.exe。
- 同时校验产品资源和有效腾讯 Authenticode 签名；重命名测试 EXE 会被拒绝。

安装与覆盖：
- 自定义安装目标拒绝磁盘根、系统关键目录、链接目录、源码目录、发布目录和未标记非空目录。
- 覆盖安装只检测精确目标目录中的助手，先请求正常关闭，再单独确认是否强制关闭。
- 安装完成后只有用户点击“确认并启动”才启动助手。

卸载与清理：
- 安装、源码、发布和绿色目录必须通过各自的专用标记与结构检查。
- 删除源码需要额外勾选及最终确认。
- 不跟随目录联接或符号链接执行递归清理。
- 用户数据删除目标必须带有效专用标记。

联网与隐私：
- 源码中唯一 HTTP 客户端位于 ReleaseUpdateChecker。
- 没有套接字监听、遥测 SDK、广告 SDK、WebView、云存储上传或远程命令通道。
- 诊断只写程序目录 diagnostics 文件夹，明确写入“不会自动上传”。

四、自动验证

Release 自动测试覆盖：
- 数量、更新偏好和自定义路径持久化；
- 页脚微信/企业微信独立实时计数及左对齐；
- 设置页切换、最右侧入口、三种主题和更新控制存在性；
- 精确路径根进程计数；
- multi_instances 原值/类型恢复、原值缺失不残留；
- 双开期间第三方写入 DWORD 7 后不被覆盖；
- 三开期间第三方写入 external-owner 后不被覆盖；
- 企业微信 1→3 编排及等待时序；
- 未签名伪客户端拒绝；
- 本地诊断路径和隐私字段；
- GitHub Release 元数据只做版本比较；
- 安装目标、运行中覆盖、显式启动确认、独立二进制、内嵌载荷；
- 微信互斥锁和 lock.ini 精确释放；
- 901×513 至最大化/超宽屏的统一比例布局。

UI 回归生成 12 个样本，包含主界面、设置页、安装器、安装完成态和清理器的日间/夜间状态。

五、软件物料清单与哈希

正式工作流在干净 Windows 虚拟机上生成：
- SHA256SUMS.txt：安装器、清理器、绿色 ZIP、主程序和 Core DLL 的 SHA-256；
- _manifest/spdx_2.2/manifest.spdx.json：Microsoft SBOM Tool 生成的 SPDX 2.2 SBOM；
- sbom-validation.json：SBOM Tool 验证结果；
- GitHub Actions 构建工件：包含通过测试的完整 artifacts/V1.0.5 目录。

七、残余风险

1. 未签名带来的 SmartScreen/信誉/启发式提示仍存在。
2. 腾讯没有承诺第三方多开机制长期稳定；新版本或组织策略可能令补开失败。
3. 企业微信四至十开没有逐版本承诺；当前真机基线只验证到三个根实例。
4. Windows 句柄处理与注册表兼容操作属于高敏感行为，可能被安全软件重点审查。
5. 注册表恢复比较不是原子事务，仍有极短竞态窗口。
6. SBOM、哈希、公开源码和反病毒结果共同提高可核验性，但不能单独证明绝对无风险。

八、候选结论

从源码和自动测试看，V1.0.5 没有发现恶意或隐私上传实现；新增功能没有突破既定安全边界。正式发布仍
以最终重建、完整测试、GitHub Actions 干净环境通过、SHA-256/SBOM 生成验证以及 Kaspersky 最终全目录
扫描全部通过为前提。
