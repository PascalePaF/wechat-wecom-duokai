# V1.1.0 全项目自查报告

审查对象：`PascalePaF/wechat-wecom-duokai` V1.1.0  
审查日期：2026-09-20（Asia/Tokyo）  
范围：一键退出、进程边界、主界面布局、主题、安装/更新/清理、构建链、测试与发布资料。

## 1. 结论

V1.1.0 新增微信与企业微信分端“全部退出”，并按用户反馈调整主界面。退出功能不是后台行为：必须先由
用户点击对应卡片的按钮，再在默认选择“否”的确认框中明确同意。核心层只把当前 Windows 会话中、
可执行文件路径与已经验证的官方客户端路径完全一致的 PID 交给关闭层；路径无法读取、会话不同、PID
已经退出或实时路径发生变化时全部跳过。

全仓库复查未发现后台上传隐私、读取聊天或账号、代码注入、隐藏持久化、远程控制、客户端文件修改、
任意进程终止或无标记任意目录删除代码。新增退出能力会在正常关闭超时后调用 Windows 进程终止接口，
这是本版相对 V1.0.11 扩大的敏感能力，已通过确认、会话、PID、实时路径和客户端类型五层边界约束。

## 2. 一键退出设计

| 阶段 | 行为 | 保护 |
| --- | --- | --- |
| 入口 | 微信/企业微信各自卡片内显示紧凑“全部退出” | 两类客户端不会互相影响；没有运行窗口时按钮禁用 |
| 确认 | 显示当前检测数量、未发送内容风险和“不注销账号”说明 | 默认按钮为“否” |
| 选择 | 从 `InstanceManager` 取得当前会话、官方精确路径匹配的 PID | 只按名称不足以进入候选集合 |
| 再验证 | 操作前重新读取进程会话与实时 EXE 路径 | 读取失败或 PID 状态变化即跳过 |
| 正常退出 | 先对所有匹配进程发送正常窗口关闭请求并等待 2 秒 | 给客户端保存状态和自行结束的机会 |
| 残留处理 | 再次实时验证后，仅终止仍残留的匹配进程 | 不提升权限，不处理拒绝访问的进程 |
| 结果 | 重新统计真实根窗口并向用户报告 | 仍有窗口时给出提示，不伪报成功 |

“全部退出”表示关闭客户端程序窗口，不等于退出或注销微信账号。由于客户端仍可能有未发送消息、文件传输
或其他处理中状态，确认框明确提醒可能的数据损失。

## 3. 界面与布局

- “应用”和“目标窗口数”外框都显式拉伸到同一工作区行，使用相同的 `42:88:14:88` 四行比例。
- 左侧两个客户端卡片分别占第 2、4 行；右侧标题、数量控件、状态说明使用相同轨道，消除视觉漂移。
- 新增退出按钮放在对应客户端的主操作区，使用低面积危险色样式，主操作“启动 / 补开”仍保持最高权重。
- 左上角只保留 Logo 与“微窗助手”，删除重复的“微信 · 企业微信”副标题。
- 页脚数字从整句文本中拆出；微信数量使用绿色粗体，企业微信数量使用蓝色粗体，并在两侧增加 8 像素留白。
- 屏幕阅读器仍可取得完整的“当前微信窗口 x 个 / 当前企业微信窗口 x 个”动态名称。

## 4. 安全复查

### 网络与隐私

- 网络端点仍只有固定 GitHub 仓库的 Release API 与用户确认更新后的 Release 附件。
- 未增加上传、遥测、广告、Socket、WebSocket、FTP、动态代码下载或未知域名。
- 不读取聊天数据库、联系人、账号、Cookie、登录凭据、剪贴板、摄像头、麦克风或屏幕。

### 进程与客户端

- 补开仍只释放白名单单实例锁，不注入 DLL、不写客户端内存、不替换客户端文件。
- 新增退出仅响应用户明确操作；不后台轮询并关闭客户端，不处理其他 Windows 登录会话。
- Windows 关闭层接收经过筛选的 PID 后仍会重新检查当前会话和实时完整路径，降低 PID 复用风险。
- 没有管理员提权；权限不足时失败关闭并向用户报告残留窗口。

### 注册表、更新和删除

- 企业微信 `multi_instances` 的落盘事务、崩溃恢复和第三方冲突保护保持不变。
- 一键更新仍要求 GitHub digest、`SHA256SUMS.txt` 与下载文件三方 SHA-256 一致，`data` 不参与替换。
- 清理仍依赖不同用途的专用标记、精确目录结构、路径范围与链接检查；本版未扩大递归删除范围。

### 构建与供应链

- 业务项目仍无 NuGet 运行包、第三方 UI DLL、自定义下载构建步骤或二进制载荷提交。
- GitHub Actions 继续使用只读权限与固定提交的官方 Action，在全新 Windows Server 2022 上重建、测试、
  复核 SHA-256 并生成/验证 SPDX 2.2 SBOM。
- 项目仍未使用 Authenticode 代码签名；未知发布者或启发式信誉告警仍可能出现，应核对正式 Release 哈希。

## 5. 自动验证

- 确认退出编排只向环境层传递当前会话中的 `10/11/20`，不会传递测试中的其他会话 PID `99`。
- 确认退出环境同时收到用户已经验证的完整客户端路径，退出后根实例从 2 变为 0。
- 启动独立测试子进程，确认 Windows 实现会重新验证实时路径并在有界等待内只结束指定 PID。
- 确认两个退出按钮、默认禁用状态、页脚粗体与留白、辅助功能动态名称和简化标题存在。
- 确认左右主卡片在 901×513、1280×720、1920×1080 及 3440×1392 逻辑下保持相同顶部与高度。
- 全部既有数量迁移、增量补开、企业微信注册表恢复、更新回滚、安装/清理、Shell 图标与锁释放测试继续运行。

## 6. 剩余限制

- 强制结束残留进程可能使尚未落盘的客户端状态丢失，因此功能必须确认且不能替代正常保存习惯。
- 微信/企业微信升级后可能改变进程名、进程树或窗口关闭行为；本工具会因无法精确验证而跳过，不会放宽到仅凭名称终止。
- 腾讯未公开承诺第三方多开机制长期稳定；应先使用测试账号并遵守客户端许可和组织安全策略。
- 反病毒未检出是证据而非绝对安全保证；正式发布的原始扫描日志、源码标签、CI、SBOM 与 SHA-256 应共同核对。
