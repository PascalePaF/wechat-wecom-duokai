微窗助手 V1.1.2 完整安全审计报告
=================================

文档编号：WD-V112-SECURITY-20260920
审计日期：2026-09-20
项目地址：https://github.com/PascalePaF/wechat-wecom-duokai

一、审计结论
------------

V1.1.2 没有加入账号、消息、聊天记录、通讯录、屏幕、键盘或凭据采集，也没有遥测、广告、远程控制、
诊断上传或后台常驻服务。新增联网逻辑只读取本项目 GitHub Release 的静态更新清单；只有发现新版本时，
才把固定 GitHub API 当作可选摘要核验。API 限流不会阻止版本检查或经过校验的一键更新。

没有发现后门、隐蔽上传、加密控制地址、访问令牌、动态下载并直接执行、DLL 注入、远程线程、计划任务、
自启动项或防火墙绕过代码。项目仍是未商业签名的开源 Windows 工具，涉及进程句柄和企业微信短期注册表
修改，可能触发安全软件启发式/云信誉告警；这类提示必须结合源码、哈希和实际扫描判断，不能直接等同于
病毒，也不能被本报告宣称为绝对安全。

二、V1.1.2 更新安全边界
----------------------

1. 最新版本入口固定为本仓库 GitHub Releases 的 latest/download/update-manifest.json。
2. 只接受 github.com 到本仓库精确版本 update-manifest.json 的 HTTPS 跳转，以及 GitHub 官方附件交付域。
3. 静态清单上限 64 KiB，产品、schema、版本、标签、发布页、最低更新器版本均须匹配。
4. setup 和 SHA256SUMS.txt 必须使用精确名称、规范 URL、受限大小和有效 SHA-256。
5. 用户确认后先校验 SHA256SUMS.txt 的清单摘要，再核对其中唯一 setup 记录和实际下载文件摘要。
6. API 可用时，服务端附件大小、URL 和 digest 还必须与静态清单一致；冲突时停止一键更新。
7. 启动安装器前在文件锁期间再次计算哈希；事务式替换、备份、回滚和目录标记约束保持不变。
8. 一键更新仍必须由用户主动确认，不会静默下载或静默覆盖。

三、请求调度与本地数据
--------------------

自动检查成功后缓存 24 小时；连续失败按 1 小时、6 小时、24 小时退避，并服从但封顶服务器 Retry-After。
启动检查有稳定的 30–300 秒错峰；安装路径只在本机参与 SHA-256 运算，不写入 HTTP 请求。手动检查立即执行。

状态保存到安装目录 data\update-state.ini，仅含检查时间、失败计数和版本号。所有软件相关运行数据继续位于
安装目录；没有回退到 AppData、注册表或隐藏系统目录。

四、敏感功能复核
--------------

- 微信：只对经过路径、文件名和腾讯签名验证的 Weixin.exe 使用已知互斥体兼容逻辑。
- 企业微信：短期 multi_instances 状态有落盘事务、崩溃恢复和外部冲突保护；不覆盖第三方的新值。
- 退出全部：只处理当前会话、精确已验证路径的目标客户端，先请求正常关闭再按确认结果处理。
- 诊断：报告保存在本机 data\diagnostics，不自动上传，且不主动采集聊天内容或账号凭据。
- 更新：只在标记过的安装版或绿色版目录执行；开发目录和身份不明目录只能手动更新。

五、构建与发布验证
----------------

GitHub Actions 使用全新 Windows Server 2022 构建并运行测试，核对 SHA256SUMS.txt，重新验证
update-manifest.json 中的 setup、校验文件和绿色 ZIP 的名称、URL、大小及 SHA-256，并生成和验证 SPDX 2.2
SBOM。V1.1.2 开始采用草稿上传全部附件后再正式发布，并启用 GitHub Immutable Releases，防止发布后替换
标签或附件。正式 CI 原件发布前执行 Kaspersky 全目录扫描，原始日志随 Release/仓库保留。

六、剩余风险与建议
----------------

1. 未购买商业代码签名证书，SmartScreen 和安全软件云信誉可能在早期下载量较低时提示风险。
2. GitHub 仓库权限仍是供应链根信任，应使用强认证、最小权限并审查发布操作。
3. 静态清单和安装包同属一个 Release；不可变发布可防止事后修改，但不能证明维护者账号永不失陷。
4. 企业微信未来版本可能改变内部实现；未经真机验证不能承诺所有历史或未来版本均可多开。
5. 病毒扫描、源码审计和哈希验证都不能提供“绝对无风险”承诺，用户应从官方 Release 下载并核对哈希。

最终判断：在公开源码、固定联网边界、严格更新校验和现有功能范围内，没有发现恶意或隐私上传行为；
V1.1.2 的更新检查相较 V1.1.1 更适合大量用户，并在 API 不可用时保持安全失败边界。
