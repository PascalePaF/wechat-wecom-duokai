# V1.2.0 退出机制与安全回归记录

日期：2026-11-04

## 确认并修复

- 旧版只结束精确主 EXE，未纳入不同名称的关联后台；即时单次快照缺少收敛窗口。改为正常关闭、可信后台清理、最多四轮关闭与有限采样；连续三个空样本确认完成。
- 根实例数被直接描述为窗口。改为分别报告可见窗口、已核验后台、访问受限、未核验候选与检查失败；诊断只添加计数。
- 旧版按 PID 重新打开进行结束，未同时约束用户 SID/创建时间。改为持有同一原生句柄核验、结束和等待，辅以只读文件租约；白名单/腾讯签名/创建时间及父子链限定族群。
- 持有退出祖先的身份来捕获迟到子进程；已核验孤儿只在本次运行保留供重试，不全局按名称批量结束。
- 启动恢复意外异常转为 RetryRequired 并阻止新的企微临时注册表会话；助手关闭后不再回写启动/退出结果。
- 主界面主题按钮循环四种实际外观，不导航；跟随系统仍在设置中，安装器/清理器保留已有日夜配对。
- 故障注入发现首次安装回滚清理被占用文件后，可能删掉中断标记却留下非空目录，导致不能直接重试。暂存清理增加有限重试与路径重定向复核，未清理完则保留已有中断标记；增加独占锁定暂存文件并在释放后重试安装的确定性回归。

## 验证与依据

采用逻辑回归、当前会话中自行创建的隔离进程、只读本机检查、全新 Windows CI、依赖/隐私/凭据检查、哈希/SBOM 与卡巴斯基扫描。未对用户正在使用的账号批量退出。

本机微信一次只读采样：3 个根实例、3 个可见窗口、45 个已核验进程，包括 15 个 Weixin 主名进程、27 个 WeChatAppEx 与 3 个 crashpad_handler。未核验候选和检查失败均为 0；未发送关闭或结束请求。该瞬时采样证明不同名称后台在本机实际存在，不代表所有版本的固定进程数量或真实账号退出实测。

只读核对本机企业微信的播放器、解码器、Flutter/agent、错误报告等辅助文件，核对到有效腾讯签名后补充名称白名单。升级、修复、卸载器和独立邮箱/微盘/会议不纳入后台清理，以免中断独立工作；名称在白名单仍必须满足用户、会话、签名和祖先证据。

Windows 的终止请求是异步操作，需要等待句柄确认完成，不能把请求成功当作已经退出。[Microsoft TerminateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)

路径/创建时间从已持有句柄读取，用户从令牌核验。[QueryFullProcessImageNameW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew)、[GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)、[OpenProcessToken](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocesstoken)

未知程序、其他副本/用户与共享服务保持边界；权限/组织保护不能保证绕过。不是穷尽式安全认证或全部客户端版本保证。
